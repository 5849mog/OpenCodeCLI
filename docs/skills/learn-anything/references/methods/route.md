# 教学模式库 · 路由

> **何时读**：判完知识类型前读本文件，按「先判知识类型」定类型，再按结果读对应套文件与工具箱，然后才实施教学。**判类型是路由起点，跳步会选错模式。**

## 一 · 教学法的来源（硬规则，先于一切）

**没有可指认来源的教学法，不许写进施工图。**

「循序渐进」「深入浅出」「由点到面」不是方法，是形容词。它们描述的是你希望达到的效果，不是你要执行的动作，所以无法执行、也无法判断有没有执行到位。

一个合格的教学法必须能说出三件事：**谁提出的 / 它的适用范围 / 它什么时候失效**。第三条最重要——所有教学法都有失效条件，不知道失效条件就会在错误的地方硬套。例如刻意练习需要即时反馈，没有反馈渠道的知识（比如「培养审美」）硬上刻意练习只会变成盲目重复。

每个方法都标了来源和证据强度：

- **【实验证据强】** —— 有重复验证的实验研究支撑，可以放心当默认做法
- **【经验共识】** —— 教学实践中广泛认可，但缺少严格对照实验，用的时候留意个体差异

**这些方法名和来源是你选路、守纪律用的，不对用户说。** 他不需要知道你在用「刻意练习」还是「worked-example fading」，他只需要知道「我先带你做一遍，然后你自己做一遍」。对用户报方法名会让他觉得自己是实验对象——见 `pitfalls.md` 第 19 条。

## 二 · 先判知识类型

先问自己：**学会之后，他要做出什么动作？** 答案决定类型。

| 类型 | 学会后要做的动作 | 典型请求 | 走第几套 |
|---|---|---|---|
| 概念理论类 | 能解释、能判断某个说法对不对 | 什么是熵 / 通货膨胀怎么发生的 / attention 是什么 | 1 |
| 技能操作类 | 能亲手做出来 | 学会用 git rebase / 学会做红烧肉 / 学会剪视频 | 2 |
| 事实记忆类 | 能准确回忆出来 | 五十音 / 元素周期表 / 常用英语单词 / 法条 | 3 |
| 解题程序类 | 能独立解出同类题 | 学会解微分方程 / 学会做动态规划题 | 4 |
| 系统全局类 | 能在脑中定位任意局部 | 看懂一个陌生代码库 / 理解医保体系怎么运转 | 5 |
| 判断品味类 | 能分辨好坏并说出理由 | 学会看设计好不好 / 学会 review 代码 / 学会挑咖啡豆 | 6 |
| 语言类 | 能听说读写产出 | 学会某个语法点 / 提高口语 / 读懂学术英语 | 7 |
| 争议立场类 | 能重建各方论证并评估 | 搞懂核电到底该不该建 / 理解 AI 监管的争论 | 8 |

**判不准时的三个决断技巧：**

- **看他会怎么「用错」。** 概念类的典型错误是用在不该用的地方；技能类的典型错误是手生做不出来。他更怕哪种错，就是哪一类。
- **两类打平时问他一句，别自己框定。** 「学会看财报」框成「怕误读数字」是系统全局类（走地图），框成「怕看不出公司有问题」是判断品味类（走成对对比）——两条路径差异巨大，而决定权在他的真实用途上，不在你的框定习惯上。一句「你更怕看不懂，还是更怕被财报骗」就能定下来，比你猜准得多。
- **一个请求可以横跨两类，但要分段，不要混着教。** 「学会用 rebase」主体是技能类，但里面「为什么哈希会变」那一小段是概念类——那一段就切出来按第 1 套走，走完回到第 2 套。混着教的结果是既没讲透也没练熟。
- **切段还是借动作，判据是「这段学会后要做出什么动作」。** 一段以「能解释」为目标、只借另一类的动作（比如手算）当验收手段，不切段；那段本身就是「能独立做出来」的新目标，才切段走那一套。

## 三 · 混合与冲突

**一个请求经常横跨两三类。** 处理原则：**主类型定整体流程，次类型切成独立段落插进去，不要混着教。**

例：「带我入门 Rust」主体是技能操作类（第 2 套），但所有权那一块是概念理论类（第 1 套，且必须配反例边界），标准库 API 是事实记忆类（第 3 套，且要在施工图里说清跨天记忆的取舍）。施工图的分段路径表里就该看出这种切换——每段标明它走哪一套。

**和用户偏好冲突时，用户赢，但要说明代价。** 他说「别让我做题，我就想听你讲」，那就讲，但在施工图的「复习与取舍」里写明：「不做产出验收，我无法判断你哪里没通，你可能会带着虚高的自我评估离开。」他知情后的选择是他的权利，你的责任是别假装这样也能学会。

**时间预算不够时，砍知识树，不砍验收。** 少学两个知识点，剩下的真学会了，比八个都过一遍全是错觉强。验收是这套框架里唯一不能省的部分——它是你能看见学习者状态的唯一窗口。
