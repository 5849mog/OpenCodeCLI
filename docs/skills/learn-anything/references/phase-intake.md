# 阶段一 · 摸底（问 + 测）

> **何时读**：规模已判（见核心文件「先判断规模」）、进入摸底前必读本文件。
> 摸底永远从「先判断能少问什么」开始，再走回合 1 点选、回合 2 诊断题；他答「不知道」时按最后一节切换。
> 摸底两步永远是两个回合——一个用点选、一个要打字，挤在一起后者就没法答（见核心文件「停下来，等他」）。

## 先判断能少问什么（但测不能省）

以下情况少问或不问，再问就是啰嗦：

- **速览型请求** —— 不问、不测、不出开场说明，直接开讲（见核心文件「速览细则」）
- **用户已经把水平说清楚了**（例：「我会写 Python 但没碰过类型标注」）—— 这本来就不问了，但**诊断题照发**。跳过的是问句，不是测：一个自称「完全门外汉」的人也可能有相邻领域的直觉，测一遍才知道从哪儿起步。
- **请求本身已经限定住了用途和规模**（例：「我想学会用 git rebase 整理提交历史」——用途是上手、规模是一次会话）—— 连点选那一回合也省掉，一句确认带过，**直接发诊断题然后停**。这类请求走完点选再走诊断题再走开场说明，是三次往返才开讲，他会先失去耐心。
- **只限定住了规模、或自述完全外行**（例：「我完全不懂财务，想学看财报，打算慢慢学」——规模已经是长程了）—— 点选那一回合**只问用途一项**，别把他刚说过的时间尺度再问一遍。他说了「慢慢学」你还问「你有多少时间」，他会觉得你没在听。
- **用户明确说「你安排就行」「随便，你决定」** —— 按**最保守**的一档默认（不是最全最深的那档），在开场说明里讲清你假设了什么，让他有机会纠正

**规模是你先预判的，不是问出来的。** 但摸底答案和预判冲突时以用户为准，立刻重切并说一句「那我们简单点，我直接给你讲透一个就行」——别闷着头按原计划走。注意这句话里不提你省掉了哪个内部步骤，他不需要知道你的流程长什么样。

## 回合 1 · 两个点选问题

用 **一次** `AskUserQuestion` 问两项就够，问完这一回合就结束：

1. **用途** —— 应付考试 / 上手做事 / 看懂别人在说什么 / 满足好奇。这一项最重要：同一个「学会 SQL」，为了面试和为了下周查数据，路径几乎没有重叠。
2. **时间预算** —— 十几分钟 / 一两个小时 / 长期慢慢学。对应核心文件的规模三档。

原来那四问里的**「现有基础」不问了**——它本来就是诊断题要测的东西，而自报的基础不可靠。**「硬约束」也不单独问**，改成在**发诊断题那一回合**顺一句「有指定的教材或材料就发我」。注意别放在点选这一回合——他的输入框被选项占住，这句话他没法回（见核心文件「停下来，等他」）。少两问就少一次往返。

**选项怎么写：**

- 每个选项写清「选它意味着什么」，用**动作**说，不要用层级编号。写「上手做事（我会安排你动手做，光听不算过）」，**不要**写「上手做事（目标 L4 能应用）」——L4 是内部刻度，见核心文件「别把脚手架给用户看」。
- 把你推荐的放第一个标注（推荐）。**用途一问推荐最保守的一档**——他只说了「想学会看财报」，你把「做投资判断」标成推荐，很可能把他的目标从「看懂」悄悄改写成「判断公司好坏」，时间预算直接爆掉。**时间一问按你的规模预判推荐**（他选了更重的档就是他的知情选择），比预判重的档放后面并写明代价。
- 选项是降低他打字成本的脚手架、不是穷举，**要明说可以走「其他」自己写**。

## 回合 2 · 诊断题

自报水平不可靠——不是用户撒谎，而是人普遍高估熟悉度、低估边界。**发 3–5 道诊断题，发完这一回合就结束，等他答。**

诊断题有双重作用：探真实起点，同时前置测验本身就提升后续学习效果（即使答错也有效，因为它把「我不知道」变成了具体的空缺）。

通用出题判据（测提取不测识别、题干不含答案）见 `questioning.md`；本节讲诊断题特有的部分。

### 怎么出

**考边界和易混，不考定义。** 定义题只能测出他有没有读过，边界题能立刻分开真懂和背过。

| 别这么问 | 改成这么问 | 它测出什么 |
|---|---|---|
| 什么是 rebase？ | 什么情况下你绝对不该用 rebase？ | 有没有真在项目里用过 |
| 什么是熵？ | 一杯热水放凉了，熵变大还是变小？为什么？ | 能不能用，还是只会背「混乱程度」 |
| 什么是复利？ | 年化 7% 十年翻多少倍？大概估一下 | 有没有数量直觉 |
| 什么是 useEffect？ | 依赖数组写空数组和不写，差别是什么？ | 是不是只会抄模板 |

### 难度要铺开

三档各一到两道：**该会的**（如果这也不会，起点比他说的低）、**边界上的**（最有信息量，多数分歧在这一档）、**略超预期的**（如果这也会，可以大幅砍知识树，直接跳到深水区）。

**用户自述完全外行时压成两档**：该会的 + 边界上的，「略超预期」那档省掉。对一个零起点的人，那一两道注定是空白——你等于自己制造了一次挫败，而它能告诉你的东西（他不会）他第一句话就说了。

**全在同一难度的诊断题等于没诊断**——要么全对要么全错，两种结果都不告诉你起点在哪。

### 发题时的话术

必须明说三件事，否则诊断题会变成考试压力：

1. 这不是考试，是定起点，答不出来完全正常
2. 不确定就写「不确定」，猜的也标一下是猜的
3. 一次全答完，答多少算多少

**「不确定」这个选项要主动给。** 他为了不显得无知而硬猜，你就拿到了污染的数据——猜对的题会让你把起点定高，后面全程超出他的水平。答不出的那几题恰好就是路径的重点。

**发完这一回合就结束，等他答。** 不要在同一回合里再调 `AskUserQuestion`——它会占住他的输入框，这几道开放题就没人能答了（回合纪律见核心文件「停下来，等他」）。

**默认用纯文本发，不要塞进 `AskUserQuestion`。** 选项式提问把作答降级成识别，测出的水平系统性偏高（判据见 `questioning.md`）。开放作答才能看见他表述里藏着的误解。

**例外：用户自述完全外行时（「我完全不懂」「零基础」），第一批题就直接用选项形式。** 别等他撞一次空白再切——他零起点这件事在他第一句话里已经说了，纯文本开放题对他只有一个结果：「我一个也答不上来」。那个回合的信息产出接近零，成本是一次往返加一次挫败感。

## 他答「不知道」时：把同一个问题做成选择题补问

**不要追问，也不要硬着往下走。** 他说不知道就是真的不知道——说明这个问法超出了他的认知范围，再换个说法问一遍只会让他更慌。

此时改用 `AskUserQuestion` 把同一个问题做成选项重问。这不是放水，是换目标：他这时要的是安全感——选项本身告诉他「原来这个问题的答案长这个样子」，他看见了可能性的轮廓就不慌了；对一个零起点的人来说，选择题不是在测量，是在给他看地图（先行组织者，Ausubel）。所以「默认开放题」的前提是他答得出；完全外行、或已经答过「不知道」的人，安全感的价值高于测量精度。

**切多少的阈值**（不给判据，这条会被执行成「一道不知道就整批重问」，那太黏了）：

- **只有一两道答「不知道」，其余答出了内容**——只把那一两道做成选项补问，其余照常往下走。他不是懵了，只是那几个点不知道，而那正是路径重点。
- **半数以上答不知道，或回复明显变短，或直接说「你直接讲吧」**——整批切成选项，这才是「我懵了」的信号。

判断看的是**他答出内容的题占多少、句子有没有变短**，不是数了几个「不知道」。

### 降级后的选项怎么设计

- **干扰项要针对真误解，不要随手编。** 问「公司报表上赚了 100 亿，是不是账上就多了 100 亿现金」，干扰项应该是「是，赚了钱账上就该有钱」——这是真实存在的想法，他选了你就知道要补哪一块。随手编的荒谬选项他一眼排除，等于白问。
- **每个选项都要是「某种人真的会这么想」**，包括正确的那个。四个里三个明显是废话，就退化成送分题。
- **给一个「都不太对 / 我想的是别的」的出口。** 这个回答的信息量往往最大——它说明他有自己的模型，只是和你给的都不一样。
- 选项本身不要用他不懂的术语，否则你只是把一片空白换成了四片空白。

**这是一条更一般的规则的特例**：用户露出「我懵了」的信号时——答不知道、回复明显变短、说「你直接讲吧」——他要的是安全感，不是更精确的问题。**给他选项，别给他更多开放题。**（另一面是提问过度，见 `pitfalls.md` 第 15 条。）
