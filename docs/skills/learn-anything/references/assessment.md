# 出题与批改

出题是这套框架里技术含量最高的动作。题出错了，闸门就形同虚设——而且是最坏的一种失效：你和学习者都以为验收过了。

---

## 一 · 出题的地基

**一道题的价值等于它能区分出什么。** 所有人都答对或所有人都答错的题，信息量为零。好题的判据只有一条：**答对的人和答错的人，脑子里的差别是你想测的那个差别。**

由此推出三条通用规则：

### 1. 测提取，不测识别

认得出（看到正确答案能选中）远比想得出（自己产出）容易。同一个知识点用选择题测，通过率能比开放题高一大截，而高出来的那部分是假的。

- **默认用开放题。** 只有在需要快速定位误解、且已经知道有哪几种典型误解时才用选择题（此时错误选项本身是探针）。
- **判断题几乎无用**，一半靠猜。要用就必须追问「为什么」。

### 2. 题干里不能含答案

最常见的形式是术语泄漏：问「rebase 的重放机制会导致什么？」——「重放」这个词已经把答案给了。改成「你 rebase 之后发现 commit 哈希全变了，为什么？」

自查方法：**把题干里所有你刚讲过的关键术语划掉，题还问得成立吗？** 划掉就问不成立的题，测的是他记不记得你的用词，不是他懂不懂。

### 3. 别只考你讲过的角度

你讲解时用的例子、切入角度、措辞，会不自觉地成为你出题的默认框架。学习者在这个框架内答对，只证明他跟得上你，不证明他能独立使用。这条是**闸门二必须派独立考官**的全部理由（见第七节）。

## 二 · 诊断题（摸底用）

**目的**：定真实起点，同时用前置测验效应给后面的学习开个空缺。**3–5 道，一次发完，普通消息发送，不要用 `AskUserQuestion`。**

### 怎么出

**考边界和易混，不考定义。** 定义题只能测出他有没有读过，边界题能立刻分开真懂和背过。

| 别这么问 | 改成这么问 | 它测出什么 |
|---|---|---|
| 什么是 rebase？ | 什么情况下你绝对不该用 rebase？ | 有没有真在项目里用过 |
| 什么是熵？ | 一杯热水放凉了，熵变大还是变小？为什么？ | 能不能用，还是只会背「混乱程度」 |
| 什么是复利？ | 年化 7% 十年翻多少倍？大概估一下 | 有没有数量直觉 |
| 什么是 useEffect？ | 依赖数组写空数组和不写，差别是什么？ | 是不是只会抄模板 |

### 难度要铺开

三档各一到两道：**该会的**（如果这也不会，起点比他说的低）、**边界上的**（最有信息量，多数分歧在这一档）、**略超预期的**（如果这也会，可以大幅砍知识树，直接跳到深水区）。

**用户自述完全外行时压成两档**：该会的 + 边界上的，「略超预期」那档省掉。对一个零起点的人，那一两道注定是空白——你等于自己制造了一次挫败，而它能告诉你的东西（他不会）他第一句话就说了。

**全在同一难度的诊断题等于没诊断**——要么全对要么全错，两种结果都不告诉你起点在哪。

### 发题时的话术

必须明说三件事，否则诊断题会变成考试压力：

1. 这不是考试，是定起点，答不出来完全正常
2. 不确定就写「不确定」，猜的也标一下是猜的
3. 一次全答完，答多少算多少

**「不确定」这个选项要主动给。** 他为了不显得无知而硬猜，你就拿到了污染的数据——猜对的题会让你把起点定高，后面全程超出他的水平。

**发完这一回合就结束，等他答。** 不要在同一回合里再调 `AskUserQuestion` 问别的——那个工具会结束回合并占住他的输入框，这几道开放题就没人能答了。

### 他答「不知道」时：把同一个问题做成选择题

**不要追问，也不要硬着往下走。** 他说不知道就是真的不知道——这个问法超出了他的认知范围，换个说法再问一遍只会让他更慌。

改用 `AskUserQuestion` 把同一个问题做成选项重问。这不是放水，是换目标：

- **他这时要的是安全感。** 选项本身告诉他「原来这个问题的答案长这样」，他看见了可能性的轮廓就不慌了。开放题对一个毫无抓手的人是一片空白。
- **此时选择题不是在测量，是在给他看地图。** 他零起点，测出来也是零，没有精度可损失；而把这个领域有哪些东西摊开给他看，本身就是有效的教学动作（先行组织者，Ausubel）。

所以本节开头「默认用开放题」那条**的前提是他答得出**。完全外行、或已经答过「不知道」的人，安全感的价值高于测量精度。

**降级后的选项怎么设计：**

- **干扰项要针对真误解，不要随手编。** 问「公司报表上赚了 100 亿，是不是账上就多了 100 亿现金」，干扰项应该是「是，赚了钱账上就该有钱」——这是真实存在的想法，他选了你就知道要补哪一块。随手编的荒谬选项他一眼排除，等于白问。
- **每个选项都要是「某种人真的会这么想」**，包括正确的那个。四个里三个明显是废话，就退化成送分题。
- **给一个「都不太对 / 我想的是别的」的出口。** 这个回答的信息量往往最大——它说明他有自己的模型，只是和你给的都不一样。
- 选项本身不要用他不懂的术语，否则你只是把一片空白换成了四片空白。

## 三 · 变式题（闸门一用，每段一道）

**目的**：验这一段是否当场掌握。

**核心机制：换掉表面特征，保留深层结构。**

- **表面特征** = 数字、名字、场景、领域外壳
- **深层结构** = 需要用到的那个关系、那个决策依据

只换表面特征的题（把 3 个提交改成 5 个提交）测的是他会不会照做；换了场景但保留结构的题（从整理提交历史换成整理一份乱掉的文档修改记录，问同样的决策逻辑）测的是他抓到了结构。

### 三种可用的变式方向

1. **换场景保结构** —— 同样的关系，搬到另一个领域。
2. **反向问** —— 讲的是「给原因求结果」，就问「给结果求原因」。反向往往难得多，且不能靠背。
3. **给一个坏例子让他改** —— 「这段代码 / 这个做法有什么问题？」诊断比生成更能暴露理解深度，因为他必须先在脑子里跑一遍正确模型才能发现偏差。

### 一段一道就够

变式题是闸门不是练习册。**一道判不出来就换一道角度不同的，不要连发五道同类题**——那既拖时间又暴露不了新信息。

## 四 · 迁移题（闸门二用）

**目的**：验「换个场景还会不会用」。这是最容易被糊过去的一关，所以由独立考官出题。

### 迁移距离要分两档

- **近迁移** —— 同领域新情境。例：教了用 rebase 压提交，问怎么用它改一个历史提交的作者信息。
- **远迁移** —— 跨领域但结构相同。例：教了熵，问为什么打乱的房间不会自己整理好，而整理好的房间会自己乱。

远迁移是真正的掌握标志，但**别拿远迁移一票否决**——远迁移失败很常见，且不代表近迁移能力不行。施工图里的目标层级到 L4 就用近迁移判，到 L5–L6 才加远迁移。

### 必出的三类题

1. **新情境应用** —— 他没见过的情境，需要主动选出该用哪个知识点。**「该用哪个」这个判断本身就是要测的东西**，所以题干里不要暗示。
2. **边界与反例** —— 「什么时候这个做法会失效 / 反过来更好？」这道题几乎无法靠记忆通过。
3. **让他自己出一道题** —— 要求：出一道能考出别人是否真懂这个知识点的题，并说明这道题为什么能考出来。

第三类最灵，值得解释一下为什么：**出题需要知道哪里容易错，而知道哪里容易错说明他有了这个知识的结构图。** 只会答题的人出不出好题——他会出一道抄课本定义的题，那个反应本身就是诊断结果。

## 五 · L1–L6 的判定细则

每级给出可当场判定的动作和对应题型。**判定时看他实际交了什么，不看他自评。**

**这张表是你判定用的，级号不要说给用户。** 对他就说「你能自己上手做出来」，不说「你达到了 L4」——见 SKILL.md「别把脚手架给用户看」。

| 级 | 达标的具体表现 | 用什么题测 | 常见误判 |
|---|---|---|---|
| L1 能复述 | 说得出定义或步骤，措辞可以近似 | 闭卷回忆 | 把「他重复了我的话」当理解 |
| L2 能翻译 | 不用术语讲给外行，且没讲错 | 「讲给一个完全不懂的人听」 | 他用了术语但你没拦，术语是理解缺口的最佳伪装 |
| L3 能举例 | 举出一个你没给过的例子，且例子真的成立 | 「举一个我没提过的例子」 | 他举的是你例子的换皮版本（数字改了、场景没变） |
| L4 能应用 | 在新情境里解决问题，过程可以有磕碰 | 近迁移题 / 动手任务 | 他在你的暗示下完成，把你的引导算成他的能力 |
| L5 能划界 | 说出失效条件和反例，且反例成立 | 边界题 / 「什么时候不该用」 | 他背了你说过的那一条边界，追问第二条就没了 |
| L6 能诊断 | 给现象能反推原因、能预测后果 | 「这个报错说明什么」/「如果改了 X 会怎样」 | 他猜对了结论但推理链是错的——**必须追问理由** |

**跨级不能跳着判。** L4 通过不代表 L2 通过——有人能照着套路做出来但讲不清（程序性会了，陈述性没会），这种人一遇到变化就崩。目标到 L4 时，L2 的「讲一遍」也要过。

## 六 · 批改：定位误解来源

**批改不是判分，是找出他的模型在哪里错了。** 说「这里不对，正确答案是 X」的代价是他把 X 记下来，而生成错误答案的那个模型还在，下一题换个形式又错。

### 三步批改

1. **先说他对的部分对在哪** —— 不是客套。明确保住已经建对的结构，否则他会连对的一起怀疑，整段重建。
2. **指出错误的来源，不只是错误本身** —— 「你说 rebase 改了原提交，这个说法来自把分支想成一根可以拖动的线；换回重放模型：原提交还在，只是没有分支指向它了。」
3. **让他用修正后的模型重答一次**——不重答就没有闭环，纠正只是听了一遍。

### 常见误解的四个来源

诊断时按这四类归因，归因准了纠正才有效：

| 来源 | 表现 | 怎么纠 |
|---|---|---|
| 类比越界 | 用你给的类比推出了类比失效区的结论 | 明确划出类比边界，别换类比 |
| 术语混淆 | 两个近义术语当同一个用 | 成对对比，给一个只有其中一个成立的例子 |
| 过度泛化 | 把某个条件下成立的规则当普适 | 给反例，让他自己补出限定条件 |
| 前置缺口 | 错的其实是更早的一个概念 | **停下回补，别在这一段继续纠**——这一段的错是症状不是病 |

**前置缺口是最需要警觉的一类。** 反复纠同一个点纠不动时，几乎总是更底层的东西没通。这时候继续在原地解释是在浪费两个人的时间，退回去补那个更早的概念。

## 七 · 独立考官 prompt 模板

闸门二用 `Agent` 派子代理当考官。**只给它目标和学习者的产出，不要给它你的讲解稿。**

理由值得再说一次：你的讲解稿会把考官锚定在你的角度上，它出的题会变成「他记住了我说的话吗」。考官不知道你怎么讲的，才出得出真正独立的新情境题。这和判断一份设计好不好要找没参与设计的人看，是同一个道理。

```
你是独立考官。你的任务是判断一个学习者是否真的掌握了某个知识，
并给出可执行的判定。你没有看过教学过程，这是刻意的——请完全基于
下面的目标和学习者的原始产出来出题和判定。

【能力目标】
（照抄施工图里的一句能力目标）

【目标掌握层级】
（例：L5 能划界。附上该级的判定标准：说出失效条件和反例，且反例成立）

【学习者的产出原文】
（逐段贴他自己写的东西 / 讲解 / 答案，保留原始措辞，不要润色，
  不要加你的评价。措辞里的破绽是重要信息。）

【已知未验收的段落】
（如实列出他喊停跳过的段落，例：第 3 段未验收）

请做三件事：

1. 出三道题，分别是：
   - 新情境应用题（他没见过的情境，且题干不要暗示该用哪个知识点）
   - 边界与反例题（什么时候这个知识不适用 / 反过来更好）
   - 元题：要求学习者自己出一道能考出别人是否真懂的题，并说明为什么这道题能考出来

2. 对每道题写出你的评分要点：什么样的回答算过，什么样的回答是
   「看起来对但实际没懂」，后者要具体描述它长什么样。

3. 基于他现有的产出原文，先给一个预判：你认为他大概会在哪道题上
   卡住，为什么。这个预判用于定位补课的位置。

输出格式：三道题 + 每道题的评分要点 + 预判。不要给学习者建议，
不要安慰性评语，判定要能直接执行。
```

### 复核时怎么派

学习者答完、补完之后，**用 `SendMessage` 发给同一个考官**，不要新派一个。它有上一轮的上下文（包括它自己的预判），复核判得更准，也能看出这次是真的通了还是换了个说法。

复核时给它：他的答案原文 + 你针对失败点补讲后他的重答。让它给最终 verdict，并明确说出「哪一级达标了、哪一级没达标」。

**没有 `Agent` / `SendMessage` 工具时**：复核由你自己做，但要先把「上一轮的三道题 + 他答错的具体位置 + 你补讲了什么」写成一份清单，再对着清单判。不要边看他的重答边回忆上一轮——那样会不自觉地放低标准：他这次说得顺了，你就以为他通了，而顺畅和正确是两件事。判完同样要声明「这一关的复核也是我自己做的，可靠性打折」。

## 八 · 出题翻车清单

| 症状 | 为什么坏 | 怎么改 |
|---|---|---|
| 题干里有刚讲过的术语 | 测的是记不记得措辞 | 划掉术语重写题干 |
| 五道题全是同一变式 | 表面练了五道，实际一道 | 每道换一个变式方向 |
| 难度全在同一档 | 全对或全错，零信息 | 铺开三档 |
| 用选择题验收掌握度 | 识别 ≠ 提取，系统性高估 | 默认开放题 |
| 只考讲过的角度 | 自我确认，测不出迁移 | 闸门二派独立考官 |
| 问「懂了吗」 | 这不是题 | 换成能判对错的动作 |
| 一次发十道题 | 他会挑简单的答，或者干脆放弃 | 3–5 道，闸门一每段一道 |
| 判对了就过，不追问理由 | 猜对和会做无法区分，L6 尤其致命 | 结论对也要追一句「为什么」 |
| 批改只给正确答案 | 错的模型还在，换个形式还错 | 归因到四类来源之一 |
| 反复纠同一点纠不动还继续纠 | 病根在更早的概念 | 停下回补前置 |
