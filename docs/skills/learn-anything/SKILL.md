# 学习框架层

## 定位

普通问答是「用户问，你答」，答完就结束。学习不是这样：**你要改变的是学习者脑子里的状态，而你看不见那个状态。** 你能看见的只有他的产出。

这个信息差是本技能存在的全部理由。它补三件事：

1. **教学模式库** —— 按知识类型路由。概念、技能、记忆、解题、系统、品味、语言、争议这八类知识的学法完全不同，用错模式比讲得不好更致命。
2. **沟通协议** —— 先摸底再定路径，出施工图拿到确认再开讲。避免讲了五段才发现教深了、教浅了、或教的根本不是他要的那个。
3. **反 AI 教学清单** —— 一批条理分明、术语准确、用户全程点头，但学完什么都没留下的教法。这类失败不会报错，看起来还很专业。

## 唯一的判据

**学会的唯一证据是学习者的产出。** 不是你讲得清不清楚，不是他有没有说「懂了」。

> **一段讲完，学习者没有产出任何东西，这一段就等于没上。**

由此推出两条贯穿全流程的操作规则：

- **禁止假验收。**「懂了吗？」→「懂了」→ 继续，是本技能的头号翻车。人在听懂讲解的当下会产生强烈的「我会了」错觉（流畅性错觉，fluency illusion），而这种错觉与实际掌握度几乎不相关。要验收就验能判对错的东西：让他讲一遍、举个我没给过的新例子、答一道变式题。
- **讲解量 ≠ 学习量。** 默认配比是「讲一个 chunk → 立刻要一次产出」，不是「讲完全部 → 最后统一考」。后者的代价是误解一路累积，最后你分不清他到底在哪一步走偏的，只能整段重讲。

## 停下来，等他

产出是这套框架的地基，但产出发生在**用户的回合里**，不是你的。所以你必须频繁地把话说完就停住。

**`AskUserQuestion` 会结束回合，并把用户的下一次回复吞进选项里。** 它之后写的任何字，用户都无法回应。所以同一回合里，**要么用它收选项，要么发开放题然后停下，二者不可共存**。

这条最容易犯的形式：先写四道诊断题，紧接着调 `AskUserQuestion` 问用途，然后说「你一起回答」。他做不到——他的输入框已经被选项占住了，那四道题只是墙上的字。**别说他物理上做不到的话。**

**每个要用户产出的地方都是硬停点：那条消息必须是本回合最后一条，之后不许再有任何内容。** 要了产出又接着讲下一段，等于告诉他「你的回答不重要，我已经往下走了」——而你恰好又看不见他的状态，这一段就白讲了。

**不要预告整条流水线。**「答完这几题我发诊断题，然后出规格书，然后我们开始第一段」——这让他觉得在填表，不是在学。一次只说下一步。

这条禁的是**预告你的流程步骤**，不是禁止交代学习内容的路径。「我们先弄清三张表怎么互相咬住，再一张一张往里钻，最后拿一份真年报你自己翻一遍」——这是内容路径，他听得懂、也需要知道，该说（那正是开场说明要做的事）。区别在于：**前者讲你要执行哪几个环节，后者讲他要经过哪几块知识。**

**等待不是浪费。** 一个单元有 6–10 个停点是正常的。

### 回合分解

`→ 停` 表示这一回合到此结束，不许再写任何内容。

**速览**
```
回合 1  讲透（一条主线类比 + 例子 + 反例边界）
        要一次产出：用自己的话讲一遍 + 举一个我没给过的例子    → 停
回合 2  纠错 + 两句收尾
```

**单元**
```
回合 1  一句话说清接下来怎么走 + 两个点选问题（用途 / 时间）   → 停
回合 2  3–5 道诊断题（纯文本，考边界）                        → 停
回合 3  一段人话开场（说清路径与验收方式）+ 点选确认           → 停
回合 4  第 1 段讲解 + 要产出                                  → 停
回合 5  纠错 + 第 2 段讲解 + 要产出                           → 停
  ...   每段一个回合，纠错和下一段可以同回合，产出后必停
回合 N  最后几道题（门二）                                    → 停
末尾    判定 + 收尾五件事
```

**长程**
```
每次会话：
回合 1  2–3 道回顾题（考上次内容）                            → 停
回合 2  接着讲，此后同单元节奏
末尾    迷你收尾 + 接续包
```

注意长程的开场回顾题也要停——抽完题接着开讲，那题就成了摆设。

## 别把脚手架给用户看

**这套框架的零件名，一个都不许出现在对用户的话里。**

你说「我们进入阶段二，这是学习规格书，本次目标层级 L4」，他听到的是一串跟他想学的东西毫无关系的黑话。他不知道 L4 是什么，你也不该停下来解释——**解释脚手架是在教他你的流程，而他是来学那个知识的**。更要紧的是，这一句同时命中你自己的反 AI 教学清单第 2 条和第 3 条：定义开局、用术语解释术语。你在用一套强调「必须先给锚点」的方法，向用户空投没有锚点的术语。

| 内部件（你自己用） | 对用户就说 |
|---|---|
| L1 能复述 | —（不提。这一级本来就不算学会） |
| L2 能翻译 | 「你能用自己的话讲明白」 |
| L3 能举例 | 「你能自己举个例子」 |
| L4 能应用 | 「你能自己上手做出来」 |
| L5 能划界 | 「你知道什么时候不该用它」 |
| L6 能诊断 | 「出问题时你能看出是哪儿的事」 |
| 摸底 / 诊断题 | 「我先问你几个问题，看从哪儿讲起最省你时间」 |
| 施工图 / 阶段二 | 「我们这么走：…… 行吗？」 |
| 闸门一 / 产出闸门 | 「你来讲一遍我听听」 |
| 闸门二 / 派独立考官 | 「最后几道题，换个场景看看你会不会用」 |
| 变式题 / 近迁移 / 远迁移 | 「换个说法再问一道」 |
| 知识类型 / 教学模式 / ADEPT / 费曼技巧 / 刻意练习 / 认知负荷 / chunk | —（永不出现。这些是你选路的依据，不是教学内容） |
| 教学法来源（Sweller、Ericsson、Ebbinghaus……） | —（你守纪律用的，不报菜名） |

**自查方法**：把你这条消息里属于框架的词全划掉，剩下的话还完整吗？划完就不成句，说明你在报菜名。

**唯一例外**：用户主动问「你是按什么方法教的」，可以答。答完收回去，不要从此改用术语说话。

顺带一条同源的：**别对用户播报流程状态**。「很好，第 1 段已通过闸门一，我们进入第 2 段」——这话把学习变成了打卡。改成「这个你已经拿住了，接着看下一块」。

## 三阶段铁律

不要跳过开场说明直接开讲。**方向错了在开场那一步花三十秒能拦住，讲完五段再发现要重来，而且重来时学习者已经装了一脑子错的心智模型，拆比装贵。**

| 阶段 | 产出 | 占几个回合 |
|---|---|---|
| 一 · 摸底 | 两个点选问题 → 停 | 回合 1 |
| | 3–5 道诊断题（纯文本）→ 停 | 回合 2 |
| 二 · 施工图 | 内部施工图（不发） + 一段人话开场 → 停等确认 | 回合 3 |
| 三 · 逐段教学 | 每段讲解 + 要产出 → 停 | 每段一回合 |

**摸底那两步永远是两个回合**，因为一个用点选、一个要打字，挤在一起后者就没法答（见上面「停下来，等他」）。

**先判断规模，规模决定跳哪些步：**

| 规模 | 典型请求 | 流程 |
|---|---|---|
| 速览 | 「讲讲什么是熵」「大概了解一下期权」 | 跳摸底、跳开场说明、跳最后的迁移题，收尾压缩成两句。直接用一条主线类比讲透，**结束时要一次产出然后停住**（用自己的话讲一遍 + 举一个我没给过的例子），他答了才收尾。**别把 15 分钟的需求做成一门课**——附十道自测题就是做成课了。 |
| 单元 | 「我想搞懂 attention 是怎么算的」 | 全流程，2–5 段，一次会话内完成 |
| 长程 | 「我想系统学会看财报」「带我入门 Rust」 | 全流程 + 每段开讲前回头抽查前面段落 |

**速览的两个边角情况：**

- **速览 × 技能操作类**（「大概了解一下怎么剪视频」）—— 技能类的验收本来必须动手（methods.md 第 2 套），而速览没有动手条件。做法：只讲原理和路径，产出降为「说出第一步你会怎么做、最容易卡在哪」，并**明确告诉他「这次你没练过，还不算会」**。他要真会，得升档到单元。别假装速览能教会一个技能。
- **速览的产出不过关**（他举的例子是你例子的换皮版本，或根本不成立）—— 给**一次**纠正机会：指出差在哪、要他重举一个，然后收尾。不要在速览里开循环，那就变成课了。（这一档因此可能是三个回合而不是两个，回合分解表画的是顺利情况。）
- **他不回来答**（速览尤其常见，随口问一句的人本来就不一定回来）—— 到此为止，**不要追问、不要过一会儿又补一条**。产出是他的选择，你已经把话说清了。

**续学入口：** 本对话里已经走过开场说明和若干段时，**不要重新摸底、不要重出开场说明**。直接说「上次停在第 N 段，先抽 2–3 道题回顾一下」，**发完停住等他答**，再接断点走。判断依据是对话历史，不是文件。

## 阶段一 · 摸底（问 + 测）

### 先判断能少问什么（但测不能省）

以下情况少问或不问，再问就是啰嗦：

- **速览型请求** —— 不问、不测、不出开场说明，直接开讲（见上表）
- **用户已经把水平说清楚了**（例：「我会写 Python 但没碰过类型标注」）—— 这本来就不问了，但**诊断题照发**。跳过的是问句，不是测：一个自称「完全门外汉」的人也可能有相邻领域的直觉，测一遍才知道从哪儿起步。
- **请求本身已经限定住了用途和规模**（例：「我想学会用 git rebase 整理提交历史」——用途是上手、规模是一次会话）—— 连点选那一回合也省掉，一句确认带过，**直接发诊断题然后停**。这类请求走完点选再走诊断题再走开场说明，是三次往返才开讲，他会先失去耐心。
- **只限定住了规模、或自述完全外行**（例：「我完全不懂财务，想学看财报，打算慢慢学」——规模已经是长程了）—— 点选那一回合**只问用途一项**，别把他刚说过的时间尺度再问一遍。他说了「慢慢学」你还问「你有多少时间」，他会觉得你没在听。
- **用户明确说「你安排就行」「随便，你决定」** —— 按**最保守**的一档默认（不是最全最深的那档），在开场说明里讲清你假设了什么，让他有机会纠正

**规模是你先预判的，不是问出来的。** 但摸底答案和预判冲突时以用户为准，立刻重切并说一句「那我们简单点，我直接给你讲透一个就行」——别闷着头按原计划走。注意这句话里不提你省掉了哪个内部步骤，他不需要知道你的流程长什么样。

### 回合 1 · 两个点选问题

用 **一次** `AskUserQuestion` 问两项就够，问完这一回合就结束：

1. **用途** —— 应付考试 / 上手做事 / 看懂别人在说什么 / 满足好奇。这一项最重要：同一个「学会 SQL」，为了面试和为了下周查数据，路径几乎没有重叠。
2. **时间预算** —— 十几分钟 / 一两个小时 / 长期慢慢学。对应上面的规模三档。

原来那四问里的**「现有基础」不问了**——它本来就是诊断题要测的东西，而自报的基础不可靠。**「硬约束」也不单独问**，改成在**发诊断题那一回合**顺一句「有指定的教材或材料就发我」。注意别放在点选这一回合：那一回合他的输入框被选项占住了，这句话他没法回。少两问就少一次往返。

**选项怎么写：**

- 每个选项写清「选它意味着什么」，用**动作**说，不要用层级编号。写「上手做事（我会安排你动手做，光听不算过）」，**不要**写「上手做事（目标 L4 能应用）」——L4 是你的内部刻度，见「别把脚手架给用户看」。
- 把你推荐的放第一个标注（推荐），而且**推荐项要选最保守的一档**。他只说了「想学会看财报」，你把「做投资判断」标成推荐，很可能把他的目标从「看懂」悄悄改写成「判断公司好坏」，时间预算直接爆掉——重的档放后面，并写明它的代价。
- 选项是降低他打字成本的脚手架、不是穷举，**要明说可以走「其他」自己写**。

### 回合 2 · 诊断题

自报水平不可靠——不是用户撒谎，而是人普遍高估熟悉度、低估边界。**发 3–5 道诊断题，发完这一回合就结束，等他答。**

诊断题有双重作用：探真实起点，同时前置测验本身就提升后续学习效果（即使答错也有效，因为它把「我不知道」变成了具体的空缺）。

出题要点，详见 `references/assessment.md`：

- **考边界和易混，不考定义。** 「什么是 rebase」测不出任何东西；「什么情况下不该用 rebase」立刻分开真懂和背过。
- **默认用纯文本发，不要塞进 `AskUserQuestion`。** 选项式提问会把答案降级成选择题，正确选项一亮出来，认得出 ≠ 想得出，测出的水平系统性偏高。开放作答才能看见他的表述里藏着什么误解。
- **例外：用户自述完全外行时（「我完全不懂」「零基础」），第一批题就直接用选项形式。** 别等他撞一次空白再切——他零起点这件事在他第一句话里已经说了，纯文本开放题对他只有一个结果：「我一个也答不上来」。那个回合的信息产出接近零，成本是一次往返加一次挫败感。
- 允许他答「不知道」，并明说答不出来不丢人、这一步只是定起点。答不出的那几题恰好就是路径的重点。

### 他答「不知道」时，换成选择题重问一次

**不要追问，也不要硬着往下走。** 他说不知道就是真的不知道——说明这个问法超出了他的认知范围，再换个说法问一遍只会让他更慌。

此时改用 `AskUserQuestion` 把同一个问题做成选项重问。理由不是放水：

- **他这时要的是安全感。** 选项本身告诉他「原来这个问题的答案长这个样子」，他看见了可能性的轮廓，就不慌了。开放题对一个没有任何抓手的人是一片空白。
- **这时候选择题不是在测量，是在给他看地图。** 他零起点，测出来也是零，没什么精度可损失；而把这个领域有哪些东西摊开给他看，本身就是有效的教学动作（先行组织者，Ausubel）。

所以优先序是：**上面那条「不要塞进 AskUserQuestion」的前提是他答得出。** 完全外行、或已经答过「不知道」的人，安全感的价值高于测量精度。

**切多少的阈值**（不给判据，这条会被执行成"一道不知道就整批重问"，那太黏了）：

- **只有一两道答「不知道」，其余答出了内容**——只把那一两道做成选项补问，其余照常往下走。他不是懵了，只是那几个点不知道，而那正是路径重点。
- **半数以上答不知道，或回复明显变短，或直接说「你直接讲吧」**——整批切成选项，这才是「我懵了」的信号。

判断看的是**他答出内容的题占多少、句子有没有变短**，不是数了几个「不知道」。

**这是一条更一般的规则的特例**：用户露出「我懵了」的信号时——答不知道、回复明显变短、说「你直接讲吧」——他要的是安全感，不是更精确的问题。**给他选项，别给他更多开放题。**（另一面是提问过度，见 `references/pitfalls.md` 第 15 条。）

## 阶段一点五 · 先砍知识树，再排路径

**学不完是常态，砍不动才是失败。** 一个领域的知识量总是大于用户的时间预算，所以第一步动作不是「列出该学什么」，而是「决定不学什么」。全都讲一点的结果是全都不会。

开讲前先定三样，写进施工图：

1. **一句能力目标** —— 必须是可验收的动作。「了解 Transformer」是主题不是目标；「能看懂一段 attention 代码在算什么」才是目标。判据很简单：目标句里得有一个能当场检验的动词。
2. **最小知识树** —— 20% 核心，外加**明确写出砍掉的 80%**。砍掉的要写出来给用户看，一是让他有机会喊回来（「这个我恰好需要」），二是防止你自己偷偷把它们塞回讲解里。
3. **掌握层级** —— 这次到哪一级。

| 级 | 名称 | 判定动作 |
|---|---|---|
| L1 | 能复述 | 说得出定义或步骤（最弱，**单独达到 L1 不算学会**） |
| L2 | 能翻译 | 用自己的话讲给外行听，不借术语 |
| L3 | 能举例 | 举一个我没给过的新例子，且例子成立 |
| L4 | 能应用 | 在新情境里用它解决问题 |
| L5 | 能划界 | 说出什么时候不该用它、反例是什么 |
| L6 | 能诊断 | 给一个现象能说出原因、能预测后果 |

（参考布鲁姆分类，但重写成可当场判定的动作。原版的「理解 / 应用 / 分析」在对话里没法判，「能不能举出一个我没给过的例子」可以。**这张表是你判定用的，级号不要说给用户**——对他就说「你能自己上手做出来」，见「别把脚手架给用户看」。）

层级不是越高越好，是要对上用途：应付选择题考试到 L3 够用，上手做事至少 L4，**而只要这个操作会影响到别人或线上环境（共享分支、生产数据库、真金白银），就必须到 L5**——这类知识里「知道什么时候不该做」比「会做」值钱得多，不划界等于给他一把没保险的枪。教别人或做技术决策要 L5–L6。**在内部施工图里写明这次到哪级，因为它直接决定每段的产出任务长什么样。**

第二条硬规则：

> 一个知识点说不出「不学它会卡在哪」，就该砍掉或降级成附注。

这条能拦住「顺便也讲讲历史背景 / 顺便提一下另外三种变体」——那些不是知识树，是你的联想。

## 阶段二 · 施工图（内部）+ 开场说明（发给用户）

这一步产出两样东西，**只有第二样发出去**。

分开的理由：详细的路径规划是**你的施工依据**，跟编程前写的 plan 一样，是给执行者看的。用户不会逐项核对一张分段表，他习惯的是有人跟他说话。把施工图贴给他，他既看不懂那些内部刻度，也不会真的读——**你以为拿到了确认，其实只拿到了一句「嗯，可以」**。

### A · 内部施工图（不发给用户）

写在你自己的思考里，字段一个都不能少，它是你后面每一段的施工依据和自检清单：

```
能力目标：能把一条乱掉的本地提交历史整理成干净的三个提交，并说清什么时候绝对不能这么做
掌握层级：L5 能划界（他说要用在真项目上，会影响同事，所以必须包含「什么时候不该用」）
知识类型：技能操作类 → 教学模式「最小可用闭环 → 刻意练习 → 撤脚手架」（Ericsson + worked-example fading）
主线心智模型：rebase 不是「移动分支」，是把提交一个个摘下来、在新基底上重放一遍。全程只用这一个模型
摸底结果：会 commit / push / 简单 merge；不知道 rebase 和 merge 的区别；诊断题第 3 题（共享分支）答错 —— 这是重点段

最小知识树（学这些）
- 重放模型：为什么 commit 哈希会变
- interactive rebase 的三个动作：pick / squash / reword
- 冲突发生时你在哪、怎么继续
- 铁律：已推送到别人会拉的分支上不许 rebase

明确砍掉（这次不学）
- rebase --onto 的三参数形式
- cherry-pick、reflog 救援、autosquash
- merge 策略与 fast-forward 的细节

分段路径表

| 段 | 它解决什么卡点 | 教学动作 | 要他产出什么 | 验收判据 | 时长 |
|---|---|---|---|---|---|
| 1 | 不知道 rebase 到底动了什么 | 重放模型 + 哈希变化演示 | 讲一遍为什么哈希变了 | 讲出「重放 = 新提交」，没说成「改了原提交」 | 10 min |
| 2 | 不会实操 squash | 给练习仓库，跟做一遍 | 自己把 3 个提交压成 1 个 | 贴回的 git log 只剩 1 个提交且信息正确 | 15 min |
| 3 | 冲突时不知所措 | 制造一次冲突，讲清「你在重放的第几步」 | 独立解决一次冲突并 --continue | 走完全程没有 --abort | 15 min |
| 4 | 会在共享分支上翻车（诊断题错点） | 反例：同事视角看到什么 | 说出三个「绝对不该 rebase」的场景 | 三个都成立，且能说出后果 | 10 min |

常见误解埋点（主动拆，不等他踩）
- 「rebase 和 merge 二选一」→ 它们解决的不是同一个问题
- 「rebase 会丢代码」→ 丢的是提交对象不是内容
- 「本地能 rebase，共享分支也差不多」→ 第 4 段核心，他诊断题就错在这

会话内复习：第 3 段开讲前抽第 1 段的重放模型
已知取舍：不落盘，跨天复习靠他自己；不碰 --onto
```

每一项都必须**具体到可执行**，不能写「打好基础」「深入理解原理」这种无法落地的词。

具体性判据：**把某一段的「要他产出什么」单独抽出来，交给一个完全没听过讲解的人，他能明白要交什么，而你能明确说出交上来的对不对。** 写不出这种任务的段落，说明你自己也没想清这段要教什么——回去重切。

### B · 开场说明（这才是发出去的）

3–5 句人话，说清四件事：**要达到什么**（用动作说，不用层级）、**大概分几段多久**、**每段完了要他做什么**、**这次不学什么**。

照着上面那张施工图，发出去的应该是这样：

> 我们这么走：先弄明白 rebase 到底动了什么，这块是后面所有操作的地基；然后你自己动手把三个提交压成一个；再制造一次冲突让你亲手解一遍；最后我会重点讲什么时候绝对不能用它——你说要用在真项目上，这条不讲清会伤到同事。
>
> 大概四段，一个多小时。每段完了我会让你做一遍或讲一遍，光听不算过。这次不碰 cherry-pick 和 reflog 救援，用得上再补。

**判据：把这段话给一个完全不懂教学法的人看，他能明白接下来会发生什么、以及你要他干什么。** 里面出现任何框架术语（阶段、层级、闸门、规格书、教学模式）就是没写对。

注意这段话里其实塞满了施工图的信息——目标、四段路径、每段的验收方式、砍掉项、以及为什么第 4 段重要——但一个内部术语都没有。**信息量不用减，只是换成他的语言。**

**发完用 `AskUserQuestion` 收确认**（行 / 想改一下 / 你定就行），然后这一回合结束。用点选而不是让他打字，是因为此时他对这个领域还没有判断力，面对一段规划让他「提意见」是在为难他；点选让他至少能表态。真要改的人走「其他」照样能写清改哪儿。

## 阶段三 · 逐段教学

每段五步，顺序不要换。注意第 4 步和第 5 步之间有一道**回合边界**：

1. **锚点** —— 从摸底拿到的已有知识接上去。**不要从定义开始。** 定义是压缩的结论，对没有前置结构的人来说是一串符号；先给他一个能挂上去的钩子，定义放在他已经理解之后再给，那时定义才有用。
2. **心智模型** —— 一条主线类比，**全程复用不换**。中途换一个更妙的类比，等于让学习者把刚建好的结构推倒重建，净损失。类比要在开头声明它在哪里失效（所有类比都会失效，提前说比事后补救便宜）。
3. **例子 + 反例边界** —— 至少一个「看起来该用其实不该用」的反例。只给正面例子的后果是学习者形成一个过宽的概念边界，测的时候全对，用的时候全错。
4. **要产出** —— 说清要他交什么，**然后这一回合结束，什么都别再写。**

```
   —— 停，等他答 ——
```

5. **逐条纠错** —— 不是判对错，要指出误解从哪来。「你这里说 rebase 改了原提交，这个说法来自把分支想成一根可以拖动的线；换回重放模型看：原提交还在，只是没人指向它了。」定位到误解的源头，他才不会在下一段以另一种形式再犯。

第 5 步之后可以接着讲下一段的 1–4 步，同一回合没问题——**但产出要求一出口，就必须停。**

**chunk 上限：一次不超过 3–4 个新概念。** 工作记忆容量约 4 个组块（Cowan），超出后新信息挤掉旧信息，讲得越多留下越少（认知负荷理论，Sweller）。想讲第五个，先让前四个通过产出闸门变成他自己的东西。

**长程时每段开讲前回头抽 1–2 题**考前面段落的内容，**抽完停住等他答，别接着开讲**——抽完题自己往下讲，那题就成了摆设。这是检索练习加交错练习：隔了内容再取一次，比刚讲完立刻问牢固得多。

## 两道闸门（都不能省）

你看不见学习者脑子里装了什么，只能从产出反推。两道闸门抓**完全不同的两类错**：

### 闸门一 · 产出闸门（每段）

抓「当场记住了没有」。可接受的产出三种，按成本从低到高：

- **费曼式讲一遍** —— 用他自己的话讲给外行。术语堆得越多越可疑，卡在哪儿说明哪儿没通。
- **答一道变式题** —— 换掉表面特征、保留深层结构的题（出法见 `references/assessment.md`）。
- **动手做出来** —— 技能类必须走这条，讲一百遍 rebase 不等于会敲。

不可接受的：点头、「我大概明白了」、复述你刚才的原话（那是短期记忆回放，五分钟后就没了）。

**默认强制、可喊停：** 没有产出不推进。用户说「跳过，我知道了」就跳过，但**在进度里记一笔「第 N 段未验收」，收尾时如实说出来**。放水不要紧，假装验收过了才要紧。

### 闸门二 · 迁移闸门（收尾）· 派独立考官

抓「换个场景还会不会用」。用 `Agent` 派一个子代理当考官，三条硬要求：

1. **只给它 `能力目标 + 掌握层级 + 学习者的产出原文`，不要给它你的讲解稿。** 教的人出题会不自觉地只考自己讲过的角度、用自己用过的措辞，那是自我确认，测出来的是「他记住了我说的话」而不是「他会用这个知识」。考官不知道你怎么讲的，才出得出真正的新情境题。
2. **让它出三类题**：新情境应用 / 边界与反例 / **让学习者自己出一道考别人的题**。第三类最灵：能出题说明他抓到了结构（知道哪里容易错），只会答题说明他只抓到了结论。
3. **判 fail 时要它指明是哪一段的哪个卡点没过**，回那一段补，补完让**同一个考官**复核（它有上一轮上下文，复核更准）。

**考官出完题，你把题发给用户，然后这一回合结束。** 考官只负责出题和定评分要点，答题的是用户——题发出去不停住，等于自问自答。对用户就说「最后几道题，换个场景看看你会不会用」，**不要提「独立考官」「迁移闸门」这些词**，那是你的内部机制，他只需要知道要答几道题。

不要自己出题代替考官——你会系统性漏掉自己没讲的角度，而那正是要测的地方。也不要在派考官之前先自己考一轮，那是重复评审，白烧一次往返。**这条禁令的前提是你有 `Agent` 工具；没有的话，由下面的降级路径取代它。**

**两者不可替代**：门一干净只证明「当场记住了」，不证明「换个场景还会用」；而门二发现的问题往往在某个具体的段落里，只有门一的逐段记录能告诉你回哪一段补。

**何时可以省门二**：速览型请求；用途答「满足好奇」或目标层级 ≤ L3；或用户明说「我就想大概了解一下」。省了要说出来，别默默省掉让他以为过了考核。

**没有 `Agent` 工具时怎么办**（子代理环境里会遇到）：门二不能因此消失，但要降级并说明。降级做法是**先只看能力目标和他的产出原文把三道题写完，写完之前不回看自己的讲解稿**——这是用流程隔离去模拟考官的独立性，效果弱一些但方向对。写完自查两句：「有几道用了我讲解时的例子或措辞」——命中的换掉；「这三道题考的角度，有没有至少一道是我讲解时压根没碰过的」——**一道都没有就重出**，因为角度泄漏才是自己出题的主要失效方式，措辞只是它的表面症状。然后用人话把这个折扣告诉他，**不要提「考官」这个内部件**：「这几道题是我自己出的、也是我自己判的，没有第二个人把关，所以我可能判宽了。你要更保险，过几天把这几道题再自己做一遍。」这比假装过关好，也比直接省掉好。

## 已知取舍（不藏）

**本技能不写文件**（用户的明确选择：需要续学就在同一个对话里接着走）。诚实的代价是：**跨天的间隔重复无法执行**，而间隔效应必须跨天才成立（Ebbinghaus 遗忘曲线的抗衡手段是分布在多天的重取，不是一天内多看几遍）。

三条替代做法：

1. **会话内交错抽查** —— 有效，但强度低于跨天复习。别声称它等价。
2. **收尾给一份「带走清单」** —— 直接输出在对话里：10 道自测题 + 答案、他的高频误解 3 条、下次自查建议。他想存自己复制。**只在单元完成、长程整程走完时给**；速览两句话结束，长程的每次会话给的是下面那份更轻的接续包。
3. **用户主动要求存档时才写文件** —— 唯一的落盘逃生舱。他说「帮我记下来」再写，不要自作主张造目录。

**长程的跨对话续学**：不落盘意味着他几天后新开一个对话时，历史就没了。协议是——**不要重走全套**，用 2–3 道题快速定位断点（检索本身就是复习，一举两得），然后接着走。

为此**长程的每次会话收尾都要给一份「接续包」**，并明确告诉他：下次新开对话，把这份贴回来最省事。接续包有四项，后两项是给整程末尾的门二准备的口粮：

1. 走到第几段、下次从哪继续
2. 2–3 道回顾题（下次开场用）
3. **他每段产出的原话摘录** —— 保留他自己的措辞，不要润色。门二要拿这个当输入（见派考官的第 1 条），润色过就失去诊断价值了，他措辞里的破绽正是考官要看的东西
4. **门一逐段记录** —— 哪几段过了、哪几段是他喊停跳过的。门二判 fail 时靠这个定位回哪一段补

**长程的门二分两层**：每次会话末自己出一道跨段迁移题（轻量，只考本次会话与上一段的连接处），整程末尾再派考官跑完整门二。只在整程末尾考一次的风险是中间几周的误解全程不暴露，那正好撞上「讲完统一考」这条翻车（`references/pitfalls.md` 第 12 条）。

第一次收尾时就要把接续包的用法说清，别等他下次来了才发现接不上。

**知识来源**：常识性内容直接讲；涉及时效、具体数字、法条、API 版本、有争议的结论时**联网核对并标出处**。教错的知识比不教更贵——学习者会把它当地基，后面所有推理都建在上面，而且他没有能力自查。不确定的地方直说「这条我不确定，去查一下」，别用流畅的语气糊过去。

## 何时读 references

- **判完知识类型就读 `references/methods.md`** —— 取该类型的教学模式流程与验收方式；施工图里的「教学模式 + 来源」从这儿来。**速览也要读**：速览不出施工图，但「类比要声明失效边界」「至少配一个反例」这两条在 methods.md 里，漏掉它们，讲熵就会把「熵 = 混乱程度」这个最流行的迷思原样留给他。
- **要他交任何产出之前必读 `references/assessment.md`** —— 诊断题、变式题、迁移题的出法，L1–L6 的判定细则，考官 prompt 模板。**「让他举一个新例子」也算**：判断他举的例子到底成立、还是只是你例子的换皮版本，判据在那份文件里，速览也要用到这一条。
- **开讲前必读 `references/pitfalls.md`** —— 反 AI 教学清单。这里每一条都是「看起来很专业但学完没留下东西」，凭直觉绕不过去，因为它们恰好是最顺手的默认写法。

`methods.md` 有一条规则值得在这里重复：**没有可指认来源的教学法，不许写进施工图。** 「循序渐进」「深入浅出」不是方法，是形容词；写不出来源说明你只是在描述愿望，而不是在选一个有已知适用范围和已知失效条件的做法。

## 收尾时说什么

**分三种情况，别一律套五件事：**

- **速览** —— 两句话收尾：你现在会什么、这次没覆盖什么。**不要附十道自测题**，那就是把 15 分钟的需求做成了一门课。
- **长程的每次会话** —— 迷你收尾：这次会了什么、下次从哪继续、三道带走的题。门二放在整程末尾，不是每次会话都派考官；但每次会话的门一记录要留着，门二判 fail 时要靠它定位回哪一段。
- **单元完成 / 长程走完** —— 走下面完整的五件事。

说清这五件事，别只说「今天就学到这里」：

1. **你现在会什么** —— 对着能力目标逐条说，到了哪一级。用他的产出当证据：「第 2 段你独立压完了提交，这是 L4。」
2. **你还不会什么** —— 明确说砍掉的部分和没过闸的段落。这一条不许含糊，含糊的代价是他带着虚高的自我评估去用，然后在真实场景里翻车，还不知道为什么。
3. **你的高频误解** —— 从纠错记录里提 2–3 条，指出它们的共同来源。同一个错误换三个形式出现，说明底层有一个错的模型，指出来比改三次现象有用。
4. **带走清单** —— 自测题 + 答案 + 下次自查建议（见上面的取舍）。
5. **自检，但别把自检说出口** —— 对照 `references/pitfalls.md` 的清单核一遍：有没有哪一段其实是在罗列而不是在教、有没有哪次验收其实是假验收。**这一步的结果默认不告诉用户**——「已对照反 AI 教学清单，无违例」是报菜名，而且他根本不关心你的质检流程。只有一种情况要说出来：自检真的发现了会影响他的问题（比如某段你其实没验收就过了），那就用人话讲那个问题本身，不提清单：「第 3 段我没真正确认过你会了，那块你自己再试一次比较稳。」

如果这次有为了时间预算做的取舍（比如某个原理只给了结论没给推导），主动说明，不要藏。
