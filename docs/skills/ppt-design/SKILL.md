# PPT 设计风格层

## 定位

自带的 `references/pptx-official/SKILL.md`（官方 `document-skills:pptx` 的完整内嵌副本）告诉你**怎么用 pptxgenjs 画出一个 pptx**。本技能补它没有的三件事：

1. **风格库** —— 可直接执行的完整预设（精确色值、字体配对、字号体系、母题、专属禁忌），而不是「选个模板」。
2. **沟通协议** —— 问清需求、出规格书、拿到确认再动手，避免做完十页才发现方向错。
3. **静默翻车清单** —— 一批不会报错、文件正常生成、但成品已经坏掉的坑（库级 bug、字体被替换、中文断错词）。

**开工前先读 `references/pptx-official/SKILL.md`**（若宿主已装官方 `document-skills:pptx`，读宿主那份即可，两者取一），API、坐标、图表、模板继承那些写法都在它那儿，本技能不重复。**两者冲突时以本技能为准**：默认值看规格书，设计看 `references/styles.md`，坑看 `references/pitfalls.md`——内嵌副本与我们的已知冲突（如官方表格示例不给 `rowH`）列在 `references/pptx-official/SOURCE.md`。

**动画与切换**：pptxgenjs 画不了动画，本技能用后处理注入补上（`scripts/inject_anim.py`，菜单制——你写中文动画脚本，工具编译成 PowerPoint 权威格式并自动验证，你不碰 XML）。**动画决策必须摆到台面上**：每份规格书都有一行「动画」，投屏演讲/发布/路演场合在这里给克制档推荐（切换 + 入场 + 全 deck 点击预算），自读/打印场合写明「不加」（负资产）；写「无」也要写出来，不许静默略过这一项。

**插图**：pptxgenjs 只会画方块和文字，画不了函数图像和几何题图。本技能同样用后处理注入补上（`scripts/inject_figure.py`）：你写中文声明式规格（点/线段/圆/弧/角标记/直角/等长/平行/函数曲线/阴影/标注），工具编译成 600dpi 透明图按锚点占位框落位，并**逐条验算你自己声明的几何约束**（等长/直角/平行/共线/中点/圆过点/角度/长度）——算错坐标会被当场拦下，不会静默交出一张与题面矛盾的图。**先写作图依据再出规格**：把读到的已知条件与作图意图用文字说清，这张图才有可对照的基准。词表覆盖不到的怪图有「自定义代码」逃生舱兜底（会标注「未受约束验算」）。考试卷/书页场景**默认裁切清洗优先**（`prep_assets.py` 的「扫描件」：白底归一 / 去斜 / 裁白边 / 对比），重绘只在需要重排、拆成多步、统一标签或做动画时才用。

**改稿场景**：用户给了现成 pptx 要整体重设计或换风格——先用 python-pptx 把每页文字提取成大纲请用户过目，然后照常走三阶段（阶段一第 3 问「内容来源」就此有了着落）。改稿默认**不动原标题**——「内容不变」优先于判断句标题规则；用户允许改文案时在规格书注明。

## 三阶段铁律

不要跳过阶段二直接写代码。**方向错了在第二阶段花三十秒能拦住，做完十页再改要重来。**

| 阶段 | 产出 | 是否需要用户确认 |
|---|---|---|
| 一 · 问清需求 | 一轮 AskUserQuestion | 用户点选即可 |
| 二 · 风格规格书 | 一段结构化文字 | **必须等确认** |
| 三 · 施工 | pptx + 预览图 | 过两道闸门后交付 |

**极小任务**（单页 + 文案已给 + 风格已点名）：阶段一可跳，规格书可压到三五行（配色 / 字体字号 / 母题 / 动画各一行），但确认与两道闸门一样不省。

---

## 阶段一 · 问清需求（一轮问完）

用 **一次** `AskUserQuestion`（最多 4 问）收齐，不要连环追问。

**先判断能不能跳过。** 以下情况直接进阶段二，再问就是啰嗦：

- 用户已经点名了风格，且只要一两页（例：「做一页新粗野主义的介绍页」）
- 用户给了参考图或参考链接 —— 参考图携带的信息比任何形容词都多
- 用户明确说「你替我定」「随便，你决定」

信息缺得多时，问这四项：

1. **场合与受众** —— 投屏演讲 / 发出去让人自己读 / 打印。这决定最小字号和每页信息密度：投屏要大字少字，自读可以密。
2. **要什么效果** —— 先问效果（舒服 / 眼前一亮 / 专业可信），**再**给匹配的风格预设。`references/styles.md` 第三节有「按效果选风格」表——用户的答案比你的审美有效得多。选项里每个预设都要后缀「来源 + 效果」，例：「蓝图纸工程风（眼前一亮 · Herschel 蓝晒 1842）」。允许收参考图（参考图 > 任何形容词）。
3. **篇幅与内容来源** —— 几页；文案由用户给还是你写；有没有数据要出图表。
4. **硬约束** —— 品牌色 / 指定字体 / logo / 中英文 / 是否需要演讲备注 / **有没有图片素材或要用的图标**（素材放工作目录 `assets/` 或给路径；我们会先清点回报、逐张确认处理方式，不自作主张改图）/ **有没有考试卷、书页的扫描件要放进来**（扫描图先做白底/去斜/裁白边，还是按题重画成干净图，清点后逐张确认）。

动画不在这四问里单独立项——它的决策点**固定在规格书的「动画」行**：写清推荐或不加的理由，随规格书一起被确认，用户点头即拍板（见阶段二模板）。

**问法要点：** 每个选项写清「选它意味着什么」，并把你推荐的放第一个标注（推荐）。风格类问题适合用 `preview` 字段放小样对比。用户对某项答不上来、说「随便」或「不知道」时，给一个带「（推荐）」的默认可选项让他点选，不要跳过问题或干等；他仍不定就按推荐走，并在规格书「已知取舍」里注明「<某项> 按推荐默认」。

## 阶段一点五 · 先把论点理顺，再动版式

**排版解决不了"没话说"。** 十页各自漂亮但没有论证推进，读者只会觉得"看着挺像，但记不住"——这种空转感是 AI 味的一大来源，而且任何配色都救不了。

动笔排版之前先写清两件事（写在规格书里，不用另起文档）：

1. **一句主张** —— 这份 deck 要让人接受的那**一个**判断。不是主题名。「Transformer 是什么」是主题；「Transformer 的本质是把'逐字读'换成'一眼看全'」是主张。
2. **3–5 个支撑论点** —— 每个论点是主张的一条腿，不是主题的一个子目录。

然后给每页派一个**论证角色**：立论 / 举证 / 转折 / 收束。规则很硬：

> **一页说不出它在论证里干什么，就该删掉或与相邻页合并。**

这条能直接拦住"十页全是并列地解释概念"——那不是论证，是词条表。

**再把主张下沉到页标题。** 每页标题写成一句判断，不写路标词：「逐字读有三个代价」在推进论证，「三个代价」只是目录。名词短语标题（「市场分析」「产品优势」「背景介绍」）和"十页并列解释概念"是同一种病。文案由你写时，每页标题（判断句）进编排表，随规格书一起被确认。

顺带一个有用的区分：**「Keynote 风格」是论证方式的请求，不是视觉风格的请求**。用户说想要"发布会那种感觉"，要的是"一个主张 + 大尺度视觉 + 揭示节奏"这种推进方式，配任何视觉风格都成立，不要去翻风格库找一个叫 keynote 的皮肤。

常见的几种论证推进方式，供定角色时参考（选一种为主，不要混）：**结论先行**（先给判断再举证，适合决策汇报）、**故事弧**（处境 → 张力 → 化解，适合提案与案例）、**逐步分解**（拆概念、讲步骤，适合教学）、**视觉主导**（大图大数字带节奏，适合发布）、**平铺速查**（等权罗列、不下判断，适合状态同步与手册）。

## 阶段二 · 风格规格书（必须等确认）

**出规格书前必读 `references/styles.md`**：预设的精确色值字号从这里取；第三节「按效果选风格」支撑阶段一第 2 问，第六节「页级编排规则」支撑本节的编排表——冲突以它为准。

按这个格式输出，然后停下等用户回话。**一次说完，不要分段挤牙膏。**

```
## 风格规格书（请确认）

**先看这里**：这份给内部评审看，要让他们一眼觉得「这是工程师做的东西」；主色是深蓝底 + 白线，整体像一张工程蓝图。
**一句主张**：Transformer 的本质是把「逐字读」换成「一眼看全」
**支撑论点**：① 逐字读的三个代价 ② 一眼看全需要的三块基石 ③ 它撑起了今天的大模型
**风格**：蓝图纸工程风
**风格来源**：Herschel 蓝晒工艺（约 1842）+ 20 世纪工程蓝图传统 —— 无来源的风格不许出现在这里
**效果承诺**：眼前一亮（技术主题的意外感；本页翻开的 1 秒落点是蓝图标题栏）
**场景判断**：投屏 · 12 人内部评审 · 最小字号 14pt
**配色**（参考调色，本次直接沿用；如按主题重推需注明取色依据）
  BG    1D4E89   蓝图蓝
  LINE  DCE7EF   白线：图框/网格/正文
  STAMP C13B2E   印泥红：唯一强调
**用色纪律**：3 个色相（底/线/点缀），底占 65–75%，点缀 ≤2% 且只给戳记与关键路径
**字体**：黑体（标题）+ 微软雅黑（正文）+ Arial（拉丁）—— 均在跨平台安全名单内
**字号体系**：主标 56 / 栏标 18 / 正文 15 / 图注 12
**版式结构**：时间轴（每页结构不连续重复，规则见 styles.md §六）
**视觉母题**（每页复现）：双线工程图框 + 右下角标题栏 + 一枚印泥红戳
**动画**：无——内部评审逐页讨论，动画只会拖节奏。（此行每份规格书必填；发布会/路演/汇报开场类场合不写「无」，改给克制档推荐，例：切换推入自底部 + 每页主张块浮入，全 deck ≤2 次点击，举证页两组内容各一次点击、其余「之后」自动接续——菜单见 `scripts/inject_anim.py` 文档头）
**图标**：不用／用 Tabler 线性，单一颜色角色（如全 INK，关键页一处 ACCENT），落点：P2 三张能力卡上方各一个，共 3 个（纪律：每页 ≤3、禁 emoji、禁「图标+圆角卡片+投影」三件套；不用的场合写「不用」）
**素材**：无／逐张声明处理方式与出处，例：「产品照.jpg → 裁切 16:9、双色调 INK+ACCENT，放 P3 右半；出处：用户提供」（未经确认不得改动素材；外部素材必须能说出处）
**插图**：无／逐张写作图依据（已知 → 作图意图 → 用哪些图元），例：「P3 二次函数 y=x²−2x−3：标顶点与 x 轴交点、阴影区间 [−1,3]；P4 直角三角形 ABC：∠A=90°、AB=4、AC=3，作斜边高 CH」。几何关系写进规格的「约束」让工具验算；扫描件写明走「裁切清洗」还是「重绘」（默认清洗优先），声明式规格与图元表见 `scripts/inject_figure.py` 文档头

**逐页编排表**（多页必填，格式必须逐页落定，不许只写"内容页×8"；页标题列在文案由你写时必填）

| 页 | 论证角色 | 页标题（判断句） | 版式结构 | 焦点元素 | 视觉载体 | 母题落点 |
|---|---|---|---|---|---|---|
| P1 | 立论 | 一眼看全，正在取代逐字读 | 单点聚焦 | 一句话主张 | 大数字 | 图框+标题栏 |
| P2 | 举证 | 逐字读正在付出三个代价 | 左右对分 | 对比箭头 | 流程示意 | 图框+红戳 |
| P3 | 转折 | 一眼看全靠三块基石撑起 | 时间轴 | 通高时间线 | 流程示意 | 图框+标题栏 |
| P4 | 收束 | 注意力已进入一眼看全的时代 | 单点聚焦 | 底部大结论 | 大数字 | 图框+红戳 |
| … | | | | | | |

编排规则（写表时逐条核；完整版见 styles.md §六）：
- 每页有论证角色 + 一句判断式标题；说不出角色的页删掉或合并
- 版式不连续重复、同结构 ≤ 全部页的 1/5、每页一个焦点、视觉载体（图/图表/示意/大数字）轮换；**强调色预算按页算**——某页已有红色焦点元素（公式图、图表强调）时，母题里的红戳要么省略要么换中性色，一页不能有两个红点
- 页眉页脚只准纯文字或 1px 细线（结构组件例外见 pitfalls #17）；封面/结束页互为独立设计，结束页收束观点

**已知取舍**：这个风格在金融、医疗、政府类场合会显得不稳重；如果受众保守，建议换深色高级感。

—— 确认后我开工。要改哪一项直接说。
```

规格书里的每一项都必须是**可执行的具体值**，不能写「高级灰」「现代感」这种无法落地的词。判据：把这套配色挪到一个完全无关的主题上会不出戏，才算够具体。

**首行「先看这里」是给非设计背景的用户看的**：用大白话写清「给谁看、要什么效果、主色和整体意象」，一到两句，别复制下面的术语（配色纪律、母题落点之类留在字段里）。用户往往只扫这一行就回话，它决定方向对不对。

阶段一第 4 问收集过的**演讲备注**在这里落地：用户要了，编排表就加一列「备注」，每页写一句「讲这页时说这句话」——不是把页面文字复述一遍。

## 阶段三 · 施工

按顺序做，不要跳步。

1. **探工具链** —— node、pptxgenjs 是否装好；渲染器用哪个（见 `scripts/render.py`）。缺什么先装，别等到要出图时才发现没有渲染器，那时你就只能盲写。
2. **核对字体真实存在** —— 列本机字体，确认规格书里点名的字体确实在。**写进文件的字体名如果本机/目标机没有，会被静默替换，字宽一变排版就散，而且预览时看不出来。** 做法见 `references/pitfalls.md` 第 1 条。
3. **把栅格与调色板写成常量** —— 画布宽高、页边距、栏宽、间距、全部色值都在脚本顶部定义，正文里只引用常量。多个模块的右边缘要锁同一个常量，否则会出现 0.05 英寸的错位。
4. **写代码前先读 `references/pitfalls.md`** —— 静默翻车清单，这里每一条都是「不报错但成品已坏」，凭经验绕不过去。然后从 `scripts/skeleton.js` 起手，它已内置绕过库 bug 的写法。要了演讲备注的：每页排版落定就 `slide.addNotes('…')` 写进文件——备注两道闸门都覆盖不到（qa 不读、judge 只看渲染图），交付前自己通读一遍。
5. **素材调理（有图片素材才做）** —— 素材放工作目录 `assets/`，成品放 `assets/_ready/`，生成脚本只引用 `_ready/`。先跑清点模式回报用户（`python scripts/prep_assets.py assets/` 打印尺寸/比例/问题），**逐张确认用途与处理方式后再处理**（`prep_assets.py assets/ spec.json`）：默认只做无损项（EXIF 转正 / sRGB / 按版面比例裁切 / 降采样到 300PPI）；双色调、灰度、颗粒是要了才做。**手机拍的卷子/书页**在规格里加 `"扫描件": true`——白底归一 → Otsu 去斜 → 裁白边 → 对比（可选 `去噪`），专治灰底、歪斜、白边、噪点；**默认裁切清洗优先、重绘按需**。**不要自作主张改用户素材**，图片出处记进交付说明。裁切会切掉原图内容——比例与锚点要写进回报让用户知道；素材图上自带的文字，图注不要复述（避免重复）；用户说「别改太多」时保留原色，并在规格书「已知取舍」里写明照片与风格可能的色彩反差。
6. **样板页确认（多页必做）** —— 先只做 P2（第一张内容页），渲染给用户看（样板在整稿里按最终页序构建时用 `render.py deck.pptx sample --pages 2` 只出这一张；样板单独成文件则 `--pages 1`）：风格、焦距、页眉页脚形态就长这样，确认后继续铺 P1 和 P3–Pn。这一张的成本是渲染一次，10 页全错的重做成本是全部。用户样板页说「换」，此时只改一页。样板页若含公式、插图或图标，先对样板做一次对应注入再渲染（步骤 7/8/9 的命令对样板同样适用），让用户看到的样板与成品一致。
7. **公式（有公式才做）** —— LaTeX 用 `$$...$$` 包裹并**独占一个文本框**（字号、颜色、位置都继承它），`python scripts/inject_math.py deck.pptx` 把它渲染成 600dpi 透明图放回原位——WPS / 真 PowerPoint / Keynote 观感一致；`--dpi 1200` 再提清晰度，`--fontset stix` 换公式字体。行内 `$...$` 不支持（图片进不了文字流）——报错时把式子改成独立文本框。mathtext 覆盖分数/根号/上下标/希腊字母/求和/积分/极限；矩阵、cases、多行 align 不支持。公式是图片：动画不能按形状名引用它。公式图不进 qa 的文字对比度检查，但会按 `formula:*` 命名做**图形对比度兜底**（<2.5 判硬伤）——深底上公式要用亮色（如线色）或加浅底托板，别把红公式直接压深蓝底（pitfalls #24）。
8. **插图（规格书「插图」行声明了才做）** —— **先把作图依据写成文字**（已知条件 / 作图意图 / 用哪些图元），再写声明式规格：`python scripts/inject_figure.py deck.pptx figures.json --colors "INK=111111,ACCENT=E4002B"`。函数图像走 `坐标轴/函数/阴影`，平面几何走 `点/线段/圆/弧/角标记/直角/等长/平行/标注`；点先命名，线段等按名字引用，坐标只写一次。**几何关系必须写进「约束」**（等长/直角/平行/共线/中点/圆过点/角度/长度）——工具逐条验算，超差即报错中止、文件不动，按实测值改坐标再跑；确实要照画加 `--force`（会大声警告）。`适配`（适应/充满宽度/拉伸）把图放进锚点占位框；图自动跟随锚点文字色，或用 `--colors` 指定角色。词表覆盖不到的怪图在「图」里写 `"自定义代码"`（可用 `ax`/`np`/`c()`，会标注未受约束验算）。`--dump-png out/` 落图供人眼与 judge 看；防重注用 `figure:*` 命名，重来加 `--replace`。扫描件走 `prep_assets.py` 的「扫描件」清洗而不是重画（除非要拆步骤/统一标签/做动画）。
9. **图标（规格书「图标」行声明了才做）** —— `python scripts/inject_icons.py deck.pptx icons.json --colors "INK=111111,ACCENT=E4002B"`：Tabler 线性图标（MIT，内嵌字体，离线可用、笔触天然统一），按**锚点形状名**定位（`{"图标":"安全","锚点":"能力卡一","位置":"内部上方居中","颜色":"ACCENT","尺寸":0.6}`），单色、每页 ≤3、禁 emoji、禁「图标+圆角卡片+投影」三件套。重复注入会被拦，重来加 `--replace`。锚点名就是施工时 `addShape/addText` 的 `objectName`（与动画同一套命名）。
10. **动画（规格书「动画」行被确认为推荐方案，或用户主动要了）** —— 按确认的方案做。菜单与脚本格式见 `scripts/inject_anim.py` 文档头：出现/淡入/浮入/飞入/缩放/擦入/强调-放大 7 种页内效果 + 淡入/推入/擦除/平滑 4 种切换，按形状名（施工时给要动的形状设 `objectName`）定位，触发分 点击/同时/之后/自动。deck 生成后先注入再过闸门：注入器自带 PowerPoint COM 三层验证（文件能打开 → 每条动画被解析且参数与脚本一致 → 方向编码往返保真），不全绿不算注入成功。样板页带动画时 PNG 看不到动画——把动画脚本逐页念给用户确认节奏。纪律：每页点击 ≤4 次、对象动画 ≤8 条，morph 的两页要有同名形状（否则退化成淡入）。
11. **闸门一：程序化检查** —— `python scripts/qa.py <文件.pptx>`，修到干净再往下（退出码 0/1/2 ＝ 干净/有硬伤/仅告警或检查降级，见下方闸门一说明）；投屏场景加 `--min-pt 14`——预设字号体系里 12pt 的图注、脚注类要**同步提到 14pt 并写进规格书**，否则必被闸门一判掉；核对用色纪律可加 `--palette`（面积占比是近似参考——背景近似、文字色不计入，也**不含戳记/公式图等强调元素**，强调色预算要另目测——用来核对纪律的角色结构，不是精确对账工具）。
12. **闸门二：渲染视觉验收** —— 渲染成 PNG（多页加 `--contact` 出全 deck 拼图，deck 级评审一眼看穿骨架复读），派 judge 子代理逐页 + 全 deck 评审，prompt 按 `references/judge-prompt.md` 填空（deck 带动画时把动画脚本、带插图时把**作图依据**一并给 judge），按 verdict 修，然后**让同一个 judge 复核**（复核轮用 `--pages` 只重渲改动的页）。

用户中途改需求：先改规格书对应行，只重做受影响的页，不必推倒重来；若波及一句主张或风格本身，回到阶段二重新确认。交付之后的修改走同一条小循环：改代码 → 闸门一 → `render.py deck.pptx --pages <改动页>` 重渲 → judge 复核改动页；改动波及规格书里的项时先改规格书再动手。

## 两道闸门（都不能省）

你写代码画幻灯片，但你看不见成品。坐标算错、文字溢出、两个框叠在一起，代码都不会报错，文件照样生成。所以必须两道闸门，而且**它们抓的是完全不同的两类错**：

**闸门一 · 程序化检查**（`scripts/qa.py`）抓「断没断」：

- 几何/排版：文字高度超框（含表格单元格）、单行超宽（会静默重排）、文本框重叠、出画布、最小字号（自动缩字按实际渲染字号判）、图片拉伸变形、画布尺寸、自动缩字与旋转提醒。宽度用 **Pillow 读真实字体度量**，不是估算——单一估算常数会同时造成误报和漏报（微软雅黑大写 A 是 0.70em、Arial Black 0.78em，而常用的估算常数是 0.55em）
- 中文排版：行首/行尾禁则、跨行劈词、孤行尾行、中文排进拉丁专用字体（渲染回退成衬线体，pitfalls #21）；纯拉丁文本这几项自动不命中，属预期
- **对比度**：文字与其下方纯色底的 WCAG 对比度（压图、图表=底色未知，跳过交闸门二）；run 没写颜色（继承主题近黑）压深底单独兜底
- 信息密度：每页字数当量粗查（拉丁字母按半字计；`--max-chars`，默认 300；投屏建议自降到 150）——它是建议阈值，用户要求保留的内容优先于建议值，放宽并在交付说明注明
- 交付合法性：OPC 包结构、单段落多个 `<a:pPr>`（PowerPoint 打开会错乱、LibreOffice 预览抓不到）、堆叠柱状图配 `outEnd` 标签（PowerPoint 报修复丢图表）、饼图超 5 块、颜色值带 `#`、硬/柔阴影混用（pitfalls #2 的互掩护变体）、关系指向空 part
- 表格外框 vs 内容：`a:ext@cy` 与 `Σ a:tr@h`、`a:ext@cx` 与 `Σ a:gridCol@w` 对不上就判硬伤——pptxgenjs 的 `addTable` 缺 `h` 时外框退化成 1 英寸、缺 `w` 时退化成 75% 页宽，真 PowerPoint 会裁掉超出部分，而 WPS/LibreOffice 自动撑开、**渲染预览 100% 看不见**（pitfalls #30）
- 字体可移植性：跨平台安全名单核对（含 macOS 苹方/黑体-简与日韩系统字体）——只核 Windows 自带不够，deck 发给 Mac 用户一样会被替换
- deck 级：连续同页眉骨架、全宽色带（页眉页脚都查）、连续无图无图表的载体断档——qa 只认图片/图表对象，若版面的载体是流程示意、大数字等（styles.md §6.5 的口径），此告警可声明豁免，交付时说明即可
- 公式残留：未转换的 LaTeX（`$$…$$` 或带 `\` `^` `_` 的 `$…$`）会显示为乱码文本，判硬伤——先跑 inject_math.py 再交付
- 图片有效 PPI：裁切后像素 ÷ 放置英寸，<72 判硬伤（必糊）、<150 告警——照片/公式/图标/插图一视同仁；注：inject_math/inject_icons/inject_figure 产出的图天然 600–800，不会误报
- 图片型图形对比度：`icon:*` / `formula:*` / `figure:*` 命名的图片按**墨色（最暗一档）** vs 所在底色兜底（<2.5 硬伤、<3.0 告警）——图片不进文字对比度检查，深底上的暗色强调（红公式压蓝图蓝、深线图上深底）靠这条拦（pitfalls #24）
- 插图几何：`figure:*` 的有效 PPI 与对比度同上兜底；**几何约束在 inject_figure.py 注入时已逐条验算**（超差不写入文件），qa 不判断几何对错——图是否忠实题面交闸门二对照「作图依据」审（pitfalls #25）
- 图标与 emoji：每页 `icon:*` 图片 >3 个告警（图标是路标不是装饰）；正文里出现 emoji 告警（反 AI 清单禁 emoji 当图标）
- 正文里的几何/数学符号：`△ □ ○ ∠ ⊥ ∥` 这类告警——中文字体把它们画成汉字的四成高、笔画细一档，看着就是 LLM 文本味（pitfalls #29）；句子里写汉字、数学式走 `inject_math`、图形用 `inject_figure`。`①`、`½` 是满尺寸的，不在此列
- 动画纪律（注入动画后）：动画引用不存在的形状 id 判硬伤（会提示修复或静默丢弃）；每页点击次数、对象动画条数、总时长超预算告警；morph 两页无同名形状（会退化成淡入）告警

检查结果按 `[S页码]` 标注，多页时逐页看，不会跨页配对。报告分三类：**硬伤**（必修）、**告警**（建议，可声明豁免）、**检查降级**——某类检查因环境缺失整类没跑（jieba 未装致劈词检查关闭、Pillow 缺席或非 Windows 无字体目录致宽度只能用估算）。**降级不等于通过**：报告顶部会单列成块、计入退出码 2，交付说明里必须声明哪类检查没执行，不得声称该项已通过。

**闸门二 · 视觉验收**（judge 子代理）抓「好不好看」：对比度之外的层次、焦点、留白节奏、观感是否地道。

两者不可替代：库级 bug（比如阴影模糊被悄悄改掉）只有读 XML 能发现；中文断错词只有看图或查断点能发现。**程序化检查干净只证明没断，不证明能看。**

**闸门二的前提与盲区（必读）**：闸门二成立的前提是「渲染器能忠实还原 PowerPoint」。当渲染回退到 **WPS / LibreOffice**（脚本会打印应用身份，`12.x` 即 WPS 兼容层），有一类结构性错误**渲染出来一定正常、真 PowerPoint 打开才坏**——最典型的是**表格外框裁剪**（pitfalls #30：WPS/LO 会按内容自动撑开表格，把过小的外框抹平）、**字体静默替换**（pitfalls #1）、**动画 timing 被丢弃**。这类问题**必须靠闸门一的结构检查或直接读 XML 兜底，不能以「预览通过」结案**。遇到验收只差这一步时，宁可多看一遍 XML，也不要相信渲染图。

### 派 judge 的硬要求（prompt 按 `references/judge-prompt.md` 填空，不要现场即兴）

1. **先渲染成 PNG 再交给 judge**，把图片路径给它。judge 只能读预渲染的 PNG，不能直接开 pptx。
2. **必须在 prompt 里声明本 deck 刻意违反了哪些通用规则**，否则 judge 会把风格特征当缺陷报回来。例：新粗野主义的粗黑描边、零模糊硬阴影、高饱和撞色、刻意旋转、无圆角是**定义性特征，不是缺陷**，反倒是柔和阴影才是失败。模板会带齐设计意图（配色纪律、字体字号、论证结构）、deck 级检查清单（版式轮换、强调色预算、载体轮换、亮点唯一性、来源忠实度、反 AI 清单）和输出格式。

judge 判 fail 时，逐条修完再让**同一个 judge** 复核（它有上一轮上下文，复核更准）。不要自己看图代替 judge，也不要在派 judge 之前先看一遍——那是重复评审，白烧一次渲染。

**没有子代理通道的会话**（比如你本身就是被派出来的子代理，再派不出下一层）：按 `references/judge-prompt.md` 填空后**自己逐条执行**这份清单代替 judge，并在交付说明里如实声明「闸门二为降级自检，缺独立 judge」。降级自检抓执行缺陷仍然有效（实测抓过十字马克压字），但缺新鲜眼光——不要默不作声地跳过闸门二。降级模式下**必须自己看渲染图**——这与上文「不要自己看图代替 judge」不冲突：那条约束的是有 judge 通道的时候。

这次诊断出的真实教训（已写入 styles.md 页级编排）：一份 10 页 deck 可以配色完全正确、文案好听、无一处溢出，但连续 8 页共用同一骨架 + 每页一条全宽页脚带 + 强调色洒满全场 + 零图片零图表——几何检查全过，成品却是标准 AI 脸。门一保证「没坏」，门二必须审「像不像人排的」。

## 交付时说什么

说清四件事，别只丢一个文件路径：

1. **文件在哪**，预览图在哪。
2. **这一页/这一份长什么样** —— 用两三句描述实际视觉效果，让用户不打开也知道自己拿到了什么。带动画的 deck 逐页念一遍动画脚本（哪页谁怎么登场、几处点击），用户不打开也知道节奏。
3. **过程中修掉了什么真问题** —— 尤其是 qa 与 judge 判出后改的那些。这既是诚实交代，也让用户知道成品是被检查过的。
4. **对照清单自检结果** —— 交付前最后一遍：那一句主张有没有真的被这些页撑起来？每页标题是不是判断句？风格是否忠实来源、用色纪律有没有守住（可贴 `--palette` 报告佐证）？效果承诺是否兑现（翻开 1 秒落点是否唯一）？有没有命中反 AI 审美清单里任何一条批量默认（含 emoji 当图标、图标家族混用、罐头示意图）？插图**逐张交代作图依据与约束验算结果**（全部通过／哪条超差被 `--force` 放行／哪张走了自定义代码未受约束验算）；图片素材**逐张列出出处**（用户提供／外部来源，外部素材必须能说出处）；闸门一输出若含**「检查降级」**，如实说明哪类检查没执行（jieba 不在就劈词没查、非 Windows 字体度量是估算）——**不得声称该项已通过**。没有违例就说"已对照，无违例"。

如果有为了风格而做的取舍（比如低对比度是风格要求、某个数字是估算），主动说明，不要藏。
