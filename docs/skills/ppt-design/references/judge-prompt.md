# judge 评审 Prompt 模板

闸门二每次派 judge 都用本模板填空，**不要现场即兴**——漏掉「刻意违例声明」是 judge 误报的头号原因（pitfalls #15）。两条硬规则：先渲染成 PNG 再派；修完后让**同一个 judge** 复核。

## 填空清单（从规格书直接抄）

| 槽位 | 来源 |
|---|---|
| `{页PNG路径列表}` | render.py 产出的 `preview/*.png`，逐页列出（多页附 `_contact_*.png` 拼图） |
| `{风格名与来源}` | 规格书「风格来源」原文 |
| `{效果承诺}` | 规格书「效果承诺」：舒服 / 眼前一亮 / 有序可信 + 1 秒落点描述 |
| `{配色纪律}` | 规格书「用色纪律」：角色数、各角色占比、点缀色只准出现的位置 |
| `{字体字号体系}` | 规格书「字体」「字号体系」 |
| `{论证结构}` | 一句主张 + 各页论证角色（P1 立论……） |
| `{动画档位}` | 「有人现场讲」或「没人讲（炫技/展映）」——从规格书「动画」行原文抄。这一档决定下面哪些条目不适用 |
| `{动画脚本}` | `inject_anim.py` 注入报告里的**分组结构**原文（每页几组、组N 是自动还是点击、每组含哪些形状、每组多长）＋每一组对应哪句话。deck 无动画则整段删掉 |
| `{插图与作图依据}` | inject_figure.py 的插图清单 + 每张的作图依据原文（已知条件 → 作图意图 → 用了哪些图元）。deck 无插图则整段删掉 |
| `{刻意违例清单}` | 本风格定义性特征（见下示例） |
| `{本风格真正的失败形态}` | judge 应当按什么判 fail |

**刻意违例示例（新粗野主义）**：3pt 纯黑描边、零模糊硬阴影、高饱和撞色、一处刻意旋转、无圆角都是定义性特征；本风格真正的失败反而是：柔和阴影、圆角、渐变、描边粗细不一。

## 作用域与禁令（派 judge 时一并交代，别省略）

闸门一（`qa.py`）**已经用真实字体度量核过**这些，**不要复测**：

- 几何：文本框溢出、出画布、文本框重叠、图片拉伸；字号下限；对比度（WCAG）；信息密度；表格外框；字体可移植性；**旋转形状 ↔ 文字的净空**（qa 已按多边形算出实测值，别再拿像素量）。

**为什么别复测**：你是按像素估的，而 PNG 里的 px→pt 换算有系统性偏差（汉字墨迹高约 0.87em，按 em 换算会低约一成——实测把 16pt 读成 14pt、18pt 读成 17.5pt）。据此报出的结论**方向可能对、数值是错的**，而这种「看着专业的错数」比不报更坏。

**你该看的，是 qa 查不到的那些**：跨页事实/数字一致性、基线与视觉对齐（qa 只查重叠与溢出）、层次与焦点、观感是否地道、动效与静态版面有没有打架（动完的位置压住文字、飞出画布）。

另外三条规矩：

- **临时文件只写临时目录**（派你时会给路径）。交付目录里的 `preview/` 是交付物，**不许往里写**裁图、拼图之类。
- **允许读施工源码**（`build.js`、`anim.json`）来核对声明的坐标与延迟——但结论里要标明「来自源码核对」，与「图里看见的」分开写。
- **数值结论标明是估读**：在静态图上做算式容易出错（实测把动画总长算少，漏了 `repeatCount`）。**看得见的现象优先于算出来的数字**；prompt 里给了数值的，以 prompt 为准。

## Prompt 模板（整段复制替换）

```text
你是 PPT 视觉验收 judge。逐页 Read 以下 PNG：{页PNG路径列表}

设计意图——你判的是「执行到不到位」，不是「我喜不喜欢」：
- 风格与来源：{风格名与来源}
- 效果承诺：{效果承诺}
- 配色纪律：{配色纪律}
- 字体字号体系：{字体字号体系}
- 论证结构：{论证结构}

【刻意违例】以下特征是本风格的定义性特征，不是缺陷，禁止报为问题：
{刻意违例清单}
本风格真正的失败形态：{本风格真正的失败形态}

逐页检查（每页独立判）：
1. 焦点唯一性：翻开 1 秒内眼睛是否落在唯一一个明确元素上；无焦点或平均分配 = fail
2. 文字可读性：对比度、字号观感、有没有被图形切穿或压住；正文里若出现 `△ □ ○ ∠ ⊥ ∥` 这类几何/数学符号、且明显比周围汉字小一号细一档 = 报（中文字体的这些字形只有汉字四成大小，是 LLM 文本味；`①`、`½` 不算）
3. 来源忠实度：这页像不像声明的来源（蓝图要像蓝图、风格派只许三原色……）；形似神不似 = fail
4. 刻意违例之外的执行缺陷：对齐、间距节奏、元素出位、图片拉伸变形
5. 图标与照片：图标语义是否准确（不可张冠李戴）、密度是否克制（每页 ≤3、不是每条要点都配）、是否单一颜色角色；照片有没有变形、风格与 deck 是否统一（必要时看是否做了双色调/裁切处理）、出处是否已声明
6. 插图忠实度（有插图时）：图是否忠实于声明的「作图依据」与题面——顶点/字母标注位置对不对、等长/直角/平行/中点等标记与文字声明是否一致、辅助线画的是不是要证的那条、坐标轴与刻度是否正确；**形似但几何关系错 = fail（比不放图更糟）**；教科书式的干净黑线是**目标**不是缺陷，但"拿通用流程骨架套内容"的罐头示意图要报

deck 级检查（看完所有页后统一判；可参照 _contact 拼图）：
- 连续两页是否同版式；同结构是否 > 全部页的 1/5
- 页眉页脚是否每页复读同一套「色带 / 角标+编号+页码」套件（规格书声明的结构组件除外）
- 强调色是否洒满全场（每页应只给一个焦点元素）
- 视觉载体（图 / 图表 / 示意 / 大数字）是否轮换，有没有连续 ≥3 页纯文字+色块堆叠
- 封面与结束页是否互相独立；结束页是否收束观点而非「谢谢」
- 是否命中反 AI 审美清单的批量默认（深蓝+霓虹青、黑金、紫粉渐变、玻璃拟态、
  emoji 图标堆、卡片方阵、通用三件套封面……）
{动画脚本槽位——deck 带动画时加这一段：}
动画编排（你看不到运动，评的是脚本与画面是否匹配）：
- 逐页动画脚本：{动画脚本}
- **先看这一档是"有人现场讲"还是"没人讲（炫技/展映）"**：{动画档位}
- 揭示顺序是否服务论证（先立论后举证、数字最后落点）；与画面焦点是否一致
- **「有人讲」档**才判下面三条（炫技/展映档下节拍数量与时长是刻意设计的，不适用，别按它判 fail）：
  - **节拍与论证单位是否对齐**：一组（一次揭示）应当是一个讲得完的论点单元——把一句话里的东西拆成好几次点，或把互不相干的几件事塞进同一次揭示，都报
  - 节拍数量是否克制：一页 >4 组（观众/演讲者要点 4 次以上）手上太忙，报；**单对象成组**（点一下只出一个东西）说明节拍过碎，也报
  - 每个节拍自身的时长是否克制（一次揭示里要播 >8s，观众在干等，报）
- **炫技/展映档**另判两条：动画是否真的**读得出意图**（有编排，不是随机堆效果）；动效与静态版面有没有**互相打架**（动完的位置压住文字、飞出画布、终态没落回版式）——这两条任何档位都判
{插图槽位——deck 带插图时加这一段：}
插图核对（看的是静态图，逐张对着「作图依据」核）：
- 逐张作图依据：{插图与作图依据}
- 顶点/字母/标注的位置与声明是否一致；等长、直角、平行、中点等标记是否与文字声明相符
- 辅助线是不是要证的那条；函数图像的定义域、关键点、阴影区间是否符合声明
- 几何关系与题面/依据矛盾 = fail（形似神不似同样算）；教科书式干净黑线是目标，不算缺陷

输出格式（严格照此，一行一页）：
{"page": 1, "verdict": "pass|fail", "issues": ["可见证据 + 所在位置 + 建议修法"]}
最后一行输出 deck 级：
{"deck": "pass|fail", "issues": ["…"]}
fail 必须给出看得见的证据（哪一页哪个元素），不许只给印象分。
```

## 复核轮

judge 判 fail → 逐条修完 → 重新渲染 → **同一个 judge** 再跑一遍上面的 prompt，开头加一行：

```text
这是复核轮。上一轮你报了以下问题：{上轮 issues 逐条}。
逐条确认是否已解决，并检查修复有没有引入新问题。
```

不要换新 judge（它没有上一轮上下文，复核不准），也不要自己看图代替 judge——那是重复评审，白烧一次渲染。
