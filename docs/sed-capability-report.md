# `sed` 能力测试报告（sed-wasm 原生引擎）

> 针对模拟 Bash 的 `sed` 命令（GNU sed → WebAssembly）的能力验证矩阵。
> 背景：原 JS 近似实现（`src/lib/tools/sed.ts` 的 `runSed`）只支持 `s/// d p q a i c` 子集，
> 无 `-E`/`-n`/`-e`/`-f`、无 `y///`、无 hold space/分支。sed-wasm 升级为完整 GNU sed。
> 结果列在 **部署后**（GitHub Pages 链接，应用内跑 bash sed）逐条实测填写。

## 测试结论

**（部署后填写）**

### ✅ 说明

- 引擎接口为「完整 argv + files 内容表」（`sed-wasm.ts`）：`-f` 脚本文件与数据文件都
  注入 MEMFS 同名副本；argv 由 bash.ts 构造。`-i` 不传引擎，由 wrapper 写回 VFS
  （Plan 模式只读拦截不变，`mutated: true` 走既有快照/UI 刷新）。
- 本地 `bun dev`（未装 emsdk）时 sed 走 JS 降级实现（`runSed`，与旧版行为一致），
  以上矩阵反映的是 **部署版（CI 构建的 wasm）** 的行为。
