## 测试结论

**45 项测试全部通过（含 2026-08-03 修复后复测）。**

### ✅ 核心能力全部正常
- 基础匹配（字面量/大小写/空结果）、正则（字符类/锚点/量词/反向引用/否定类）、特殊字符转义、上下文显示（before/after/context）、范围限定（path 递归）、计数统计、管道联动均工作正常。
- 中文/Emoji/特殊符号、超长行、二进制乱码文件、Tab 缩进均正确处理。
- 结果上限 cap=100 会给出 TRUNCATED 提示并建议缩小范围。

### 🆕 2026-08-03 修复的两处局限
1. **编号 23（限定文件类型）**：`search_files` 新增 `include` / `exclude` 参数（支持单字符串或字符串数组），语义对齐 grep `--include=*.ts` / `--exclude`。每个 glob 同时匹配文件的**完整路径 / 相对 search path 的路径 / basename** 三处，故 `include:'*.ts'` 与 `include:'src/**/*.ts'` 均可用。此功能在 `glob` / bash `grep` 中原本就存在（`glob` 的 pattern 即 glob；bash grep 支持 `--include`）。
2. **编号 45（不存在路径）**：`search_files`、`glob`、`search_symbols` 三个搜索工具在 `path` 指向不存在的路径时，统一返回 `ok:false` 的 `Path not found: <path>` 友好报错（附带"检查路径或传 '' 搜索整个工作区"提示），不再静默返回 "No matches found"，可区分"路径写错"与"确实无匹配"。

### 📌 其他值得注意的行为
- **regex 开关**：工具默认是**字面量模式**（`regex=false`），`. * [ ]` 等元字符默认按字面量处理；只有显式 `regex: true` 才启用正则语义。这是设计上的安全默认，但用户需明确区分。
- **逐行匹配**：不支持跨行匹配（`\n` 不参与，`.` 不跨行）。
- **非重叠匹配**：`aaaa` 中搜 `aa` 得到非重叠结果（位置0和2）。
- **无 Unicode 大小写折叠**：`ß` 与 `ss` 不视为等价，`straße` 不匹配 `STRASSE`。
